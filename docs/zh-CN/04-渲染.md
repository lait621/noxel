# 渲染

`noxel-render` 在一个场景之上提供两个渲染器 —— 一个按瓦片（tile）分箱的软件
光栅化器和一个 CPU 光线追踪器 —— 外加一个混合模式：光栅化主可见性，光线追踪次级效果。设计记录：
`docs/adr/0003-software-renderer-first.md`、`0004-dual-renderer.md`、
`0005-color-management.md`。

## 三种着色模式

`ShadingMode` 选择投射哪些光线，而不是绘制哪个场景。三者消费同一个 `Scene`、
`CameraView`、`VisibleSet` 和 `RenderSettings`，并且都写入同一个 `Framebuffer`。

| 模式 | 主可见性 | 阴影 | AO | 反射 | 色调曲线 |
|---|---|---|---|---|---|
| `Raster` | 光栅化器 | 阴影贴图 | — | — | `None` |
| `Hybrid` | 光栅化器 | 光线追踪 | 光线追踪 | —（设置项存在，但这个通道不投射它们） | `None` |
| `Raytrace` | 光线追踪器 | 光线追踪 | 光线追踪 | 光线追踪 | `Aces` |

```rust
use noxel_render::renderer::{RenderSettings, ShadingMode};

let fast = RenderSettings::fast();     // Raster, 512 shadow map, no AO
let still = RenderSettings::quality(); // Hybrid, 2048 shadow map, AO, 4 spp
let _ = (fast.mode, still.mode);
```

| 情形 | 用 | 原因 |
|---|---|---|
| 60 Hz 的游戏过程 | `Raster` | 对瓦片跑一遍，外加一个只写深度的阴影通道 |
| 截图、有光照的 3D 观感场景 | `Hybrid` | 主图像保持像素对齐；昂贵的射线全是次级效果 |
| 黄金图像、对比截图 | `Raytrace` | 另外两者所对照的参考 |

没有提交任何基准数字，所以把开销当作一个工作量模型。在默认的 320x180
（57 600 像素）下：

| 模式 | 每帧工作量 | 主要开销 |
|---|---|---|
| `Raster` | 57 600 个主像素 + 一个 1024² 的只写深度通道 | 片元着色，然后是阴影贴图光栅化 |
| `Hybrid` | 那个光栅通道（阴影贴图关闭）+ 至多 `ray_budget` 条次级光线 | 光线预算，而不是像素数 |
| `Raytrace` | 每像素 `samples_per_pixel` 条主光线，每条都递归进阴影/AO/反射光线 | 主光线；`ray_budget` 默认为 400 000 |

三者都是确定性的 —— 没有任何通道读取时钟、线程 id 或全局 RNG
（`docs/adr/0008-deterministic-rendering.md`）。

## 光栅化器

```text
scene -> vertex transform -> near-plane clip -> backface cull -> screen triangles
      -> tile binning -> per-tile raster -> shading (lights + shadow + fog + texture)
      -> transparent pass (back to front) -> post -> resolve
```

**32x32 瓦片。** `TILE_SIZE` 是 32，所以 320 宽的一帧正好是十个瓦片，一个瓦片的
三角形列表能留在 L1 里。`TileBins` 是一次计数排序（一趟计数、一次前缀和、一次
散布），所以每个瓦片的三角形是连续的，内层循环永远不会遍历整个场景。

**行带并行。** 帧缓冲切分成整*瓦片*行的行带 —— 有 job pool 时每个行带四行瓦片，
没有时整个帧一个行带。`Framebuffer::split_mut()` 一次交出颜色、深度和 id 切片，
`split_at_mut` 切出互不重叠的每带切片，因此并行路径不需要锁或逐像素原子操作。
两条路径都跑同一个 `raster_tile_in_band`，而
`parallel_and_sequential_rendering_agree` 断言它们产生完全相同的像素。

```rust
use noxel_core::jobs::JobPool;
use noxel_render::raster::RasterRenderer;

let mut r = RasterRenderer::new(320, 180).with_jobs(JobPool::new(4));
r.set_shadow_map_size(1024);
assert_eq!(r.name(), "software-raster");
```

**填充规则。** 没有它，正好落在共享三角形边上的每个像素都会被着色两次 —— 沿细分
地面接缝出现一条深色拼布，透明四边形上出现一条更暗的对角线。只要像素到某条边的
距离在 `TIE_EPSILON` 之内，`tie_owner(a, b)` 就只在边的第一个端点更大（先比屏幕
Y，再比 X）时接受它。每个闭合且绕向一致的面，其两个三角形都会以相反方向穿过共享
边，所以恰好一个三角形认领该像素，且无需做绕向分类讨论。

**深度与裁剪。** 深度是投影原生的 `[0, 1]`，所以测试是 `depth > stored => reject`
—— 更近或相等者胜出，无需重映射。三角形在投影*之前*对 `w > 1e-5` 裁剪：一个顶点
在内时变成一个三角形，两个顶点在内时变成一个四边形，再扇形三角化。`edge` 函数是
通常那个函数的**取反**，所以正面有正面积，`emit_clipped` 和像素循环都依赖这个
符号 —— 要改就一起改。插值是透视正确的（每顶点 `1/w`，再除回去）。实例 id 落在
id 缓冲里；未被触碰的像素保持 `Framebuffer::NO_ID`。

## 阴影贴图

一张方向光贴图，拟合到一个跟随相机的窗口：俯视世界有数公里宽，覆盖它的单个体
每纹素会有数厘米。

| 步骤 | 发生什么 |
|---|---|
| 拟合 | `ShadowMap::begin(direction, camera.position, extent, range, true)` 围绕光源构建一组基，把相机投影到其上，**把该投影取整到整数纹素**，再投影回去 |
| 为什么要吸附 | 不这样做的话，体会亚纹素级滑动，每条阴影边缘都会爬行 |
| 范围 | `Light::Directional::shadow_extent`（默认 40 m），深度范围为 `extent * 4` |
| 通道 | 一个最小的裁剪空间、只写深度的光栅化器，接受两种绕向 —— 从光源看一个闭合网格会有混合朝向，而单面贴图会漏光 |
| 过滤 | `sample_pcf`：四次双线性采样；在体外返回 `1.0`（受光），这掩盖了移动的窗口 |
| 偏置 | `shadow_bias`（0.0015）加上 `max(0.02) * 8` 世界单位的法线偏移 |

只有 `Light::Directional` 使用这张贴图；点光源和聚光灯的阴影来自光线追踪路径。

## 透明通道

`AlphaMode::is_transparent()`（`Blend`、`Additive`）把三角形送进第二个通道，它按
**实例**到相机与包围盒中心的距离从后往前排序（逐三角形排序会更准确，但会摧毁
批处理），然后把每个实例的三角形作为一个子集绘制。它做深度测试但不**写**深度，
这正是第一个透明面之后第二个透明面仍能被看见的原因。`Opaque` 和 `Cutout` 留在
不透明通道；`Cutout` 丢弃低于阈值的部分并把其余当作不透明，所以植被与世界一起
排序。

`Additive` 真正地**相加**：片元的辐射度乘以其 alpha 后累加到目标上，而不是按
source-over 合成。这正是该模式的意义所在 —— 火球、灯光辉光或魔法闪光应该*照亮*
它后面的东西，而按 source-over 合成反而会压暗背景，完全反了。在 320x180 的内部
分辨率下，效果就是整个像素，差别并不细微。

由于线性辐射度无上界，加法输出可以超过 1.0；`Framebuffer::resolve` 中的色调曲线
把它拉回来（见颜色一节）。

## 光线追踪器

- **加速结构。** `TriangleBvh` 由变换后的三角形汤构建，并针对 `Scene::revision()`
  缓存，所以静态场景只付一次代价。`triangle_count()`/`bvh_depth()` 暴露它；
  `release_cached()` 丢弃它。
- **采样。** 光线来自 `sampling::Sampler`，它是 `(x, y, frame, sample)` 的纯函数
  —— Hammersley 点加逐像素抖动，没有全局 RNG。
- **主光线。** 正交相机在 `ortho_height` 范围内生成平行光线；透视相机由 `fov_y`
  构建；两者都在像素内抖动。
- **预算。** `ray_budget`（400 000）是硬性上限：宁降质量，也不让这一帧爆掉。
  `samples_per_pixel`（1）是其中的质量旋钮。
- **AO。** 四个按 `hammersley(i, 4)` 分层并抖动的余弦加权半球采样，投射距离到
  `ao_radius`（1.5 m）。`ao_strength`（0.6）在无遮挡与全遮挡之间混合。需要
  `ambient_occlusion: true`。
- **反射。** 对 F0 = 0.04 的 Schlick 菲涅尔（由 `metallic` 向基础色插值），按
  `1 - roughness` 衰减，且只在 `roughness < 0.999` 时生效；方向是一个偏向镜面
  方向的锥形采样；递归在 `reflection_bounces`（1）处停止。
- **时域累积。** 当 `temporal_blend > 0` 时，每帧混合进一个累积缓冲（第一帧整帧
  取用该采样）；`reset_accumulation()` 在切换后丢弃历史。为 `0` 时该缓冲只作
  暂存，所以后处理没有时域成分。
- **未命中。** 场景有雾时取雾色（没有地平线接缝），否则取背景色，并按
  `ray.dir.y` 向更亮的地平线混合。
- **双面着色。** 插值法线背向光线的命中会被翻转，使表面仍被照亮。
- **已记录的限制。** 透明材质不会被透射或折射；追踪器把它们当作不透明渲染一次。

```rust,no_run
use noxel_render::Framebuffer;
use noxel_render::raytrace::RayTracer;
use noxel_render::renderer::{CameraView, RenderSettings, ShadingMode};
use noxel_render::scene::Scene;

let mut tracer = RayTracer::new(320, 180);
let mut scene = Scene::new();
let camera = CameraView::default();
let mut target = Framebuffer::new(320, 180);
let settings = RenderSettings {
    mode: ShadingMode::Raytrace,
    samples_per_pixel: 4,
    ..RenderSettings::default()
};
let stats = tracer.render(&scene, &camera, None, &mut target, &settings);
let _ = (&mut scene, stats);
```

## 混合管线

混合模式在阴影贴图**关闭**的情况下运行光栅化器 —— 阴影马上要由光线追踪产生
—— 然后遍历每个有几何的像素：

1. `Framebuffer::unproject_depth(x, y, inv_view_projection)` 把存储的深度变成
   世界位置；深度 `>= 1.0` 是背景，会被跳过。
2. `reconstruct_normal` 由右邻和下邻的深度重建法线。如果任一邻居比
   `camera.far * 0.05` 远得多，这个差就是轮廓边而不是切线，于是使用回退值
   `-camera.forward` —— 这就是不需要法线缓冲的原因。
3. 一条太阳可见性光线把被遮挡的像素乘以 **0.35**，而不是 0，所以混合阴影是一种
   柔和的压暗。
4. AO 是在 `ao_radius` 内的四条分层余弦光线；像素乘以
   `1 - ao_strength * (1 - ao)`。
5. 只有因子低于 0.999 的像素才被写回。

两个光线循环都计入 `ray_budget`。

## 后处理

`PostProcess::apply` 在 resolve 之前的**线性 HDR** 缓冲上运行，所以一个效果可以
把值推过 1.0，再让色调曲线拉回来。暂存缓冲由 `PostProcess` 实例持有，因此这条链
不会逐帧分配。

| 设置 | 默认值 | 效果 |
|---|---|---|
| `gain`、`lift` | 1.0、0.0 | `rgb = rgb * gain + lift`，在零处截断 |
| `desaturate` | 0.0 | 向亮度混合 |
| `bloom_threshold`、`bloom_intensity`、`bloom_radius` | 0、0、4 | 亮部提取，两次可分离盒式模糊（先用半径，再用 2×），加回 |
| `vignette`、`vignette_radius` | 0.0、0.6 | 由到角落的距离决定的平方衰减 |
| `scanline_period`、`scanline_strength` | 0、0.0 | 每隔 `period` 行压暗 |

`PostSettings::default()` 全部关闭 —— 像素风引擎不该未经要求就给艺术家的调色板上
色；`cinematic()` 和 `retro()` 是预设，`is_identity()` 会短路整条链。`apply` 内部
的顺序：gain/lift、去饱和、泛光、暗角、扫描线。

抖动是例外：它属于量化，所以住在 `Framebuffer::resolve` 里，名为
`dither_strength`，是在 sRGB 转换之前于线性空间施加的 4x4 Bayer 偏移。

## 帧缓冲与 resolve

| 缓冲 | 类型 | 布局 |
|---|---|---|
| 颜色 | 每像素 `f32 * 3` | **线性** HDR RGB |
| 深度 | 每像素 `f32` | `[0, 1]`，`1.0` 是远平面 |
| id | 每像素 `u32` | 实例 `user_data`；没有绘制时是 `Framebuffer::NO_ID` |

`resolve(&ResolveSettings)` 是引擎离开线性空间的唯一地方：曝光、色调曲线
（`None`、`Reinhard`、`Aces`）、可选的抖动，然后 `linear_to_srgb()`。在默认值下
—— `ToneMap::None`、曝光 1.0、不抖动 —— 颜色来自调色板的无光照表面会精确往返成
作者写下的那个字节（`unlit_sprite_round_trips_to_the_authored_palette`、
`palette_round_trips_exactly`）。

```rust
use noxel_render::framebuffer::{Framebuffer, ResolveSettings, ToneMap};

let mut fb = Framebuffer::new(320, 180);
let exact = fb.resolve(&ResolveSettings::default());
let graded = fb.resolve(&ResolveSettings { tonemap: ToneMap::Aces, ..ResolveSettings::default() });
let _ = (exact, graded);
```

`resolve_palette(&settings, &palette)` 是同一次 resolve，只是每个像素都吸附到最近
的调色板项，且在 sRGB 空间（艺术家挑颜色的地方）中进行。

**色调曲线自动跟随渲染器。** `RenderSettings::resolve()` 在 `mode` 字段为
`Raytrace` 时选择 `Aces`，而 `App::resolve()` 取用的模式来自 `config.mode` —— 也就是
这一帧真正用来渲染的模式 —— 而不是盲目信任 `config.render.mode` 里恰好是什么。
因此只调用 `AppConfig::with_mode()` 就够了：光线追踪的一帧会带曲线解析，而光栅的一帧
仍然以 `None` 逐字节精确解析。

## 像素风规则

1. **内部分辨率固定。** `AppConfig::internal` 默认为 320x180；场景在那里渲染，再
   被放大。改变窗口大小绝不能改变场景的像素数，否则精灵会闪烁。
2. **按整数倍放大。** `Viewport::pixel_art(w, h, iw, ih)` 给出 `integer_scale()`
   （向*下*取整，所以没有像素被重复两次）、`scaled_size()`、`letterbox_offset()`
   和 `internal_aspect()`。
3. **吸附相机，而不是精灵。** `PixelPerfect::at(320, 180)` 设置 `snap_focus` 和
   `snap_sprites`。`snap_to_pixels(world_size, units_per_pixel)` 取整的是*尺寸*，
   同时让位置保持连续 —— 这是精灵移动时在 15 px 与 16 px 之间来回跳的标准修法。
4. **最近邻采样加半纹素内缩。** `Texture::sample_pixel_art` 吸附到纹素中心，所以
   位于图集单元格边界上的 `u` 解析到左/上纹素，而 `u == 1.0` 解析到最后一个纹素
   而不是回绕。
5. **无光照材质精确往返。** `Material::default()` 有意设置 `unlit: true`：引擎
   渲染的是手工创作的像素画，拿艺术家没要求的光照去给他惊喜，比让光照必须被主动
   打开更糟。

## 材质

```rust,no_run
use noxel_core::math::Color;
use noxel_render::material::Material;

// `texture_handle` is a `TextureHandle` from `Scene::add_texture`.
let flat    = Material::unlit("flat", Color::from_hex(0xFF00_FF00));
let sprite  = Material::sprite("sprite", texture_handle);
let terrain = Material::lit("terrain", Color::WHITE);
let leaves  = Material::foliage("leaves", texture_handle, 0.5);
let glass   = Material::transparent("glass", Color::rgba(0.6, 0.7, 0.8, 0.4));
let lamp    = Material::emissive("lamp", Color::from_hex(0xFFFF_E0A0), 2.0);
let tiled   = flat.with_uv_scale(noxel_core::math::Vec2::new(4.0, 4.0));
let _ = (sprite, terrain, leaves, glass, lamp, tiled);
```

| 构建器 | `unlit` | alpha 模式 | 说明 |
|---|---|---|---|
| `unlit(name, color)` | true | `Opaque` | 像素游戏里最常见的材质 |
| `sprite(name, texture)` | true | `Opaque` | 带纹理的无光照 |
| `lit(name, color)` | false | `Opaque` | 粗糙度 0.95 |
| `foliage(name, texture, threshold)` | true | `Cutout` | 双面 |
| `transparent(name, color)` | true | `Blend` | |
| `emissive(name, color, strength)` | true | `Opaque` | 黑色基色，`cast_shadow = false` |

修饰方法：`with_texture`、`with_uv_scale`、`with_alpha_mode`、`with_lit`、
`without_shadow_casting`。其他字段：`base_color`（线性）、`emissive`、`roughness`
（0 为镜面 → 1 为哑光）、`metallic`、`specular`、`receive_shadow`、`cast_shadow`、
`double_sided`、`uv_scale`/`uv_offset`、`palette_snap`。`sort_key()` 把状态分组
标志打包进一个 `u32`。

| `AlphaMode` | 写深度 | 通道 | 用于 |
|---|---|---|---|
| `Opaque` | 是 | 不透明 | 一切实心物体 |
| `Cutout { threshold }` | 是 | 不透明 | 植被、栅栏、格栅 |
| `Blend` | 否 | 透明，排序 | 玻璃、水、淡出的屋顶 |
| `Additive` | 否 | 透明，排序 | 辉光、火焰、魔法 —— 真正地加光 |

## 灯光、环境光与雾

`Scene::lights` 是公开的 `Vec<Light>`；`add_light` 追加；`primary_sun()` 返回第一个
`Light::Directional`，阴影贴图和混合阴影通道用的就是它。

| 构造函数 | 变体 | 默认值 |
|---|---|---|
| `Light::sun()` | `Directional` | 方向 `(-0.35, -1.0, -0.25)` 归一化，暖白，强度 1.0，`cast_shadow: true`，`shadow_bias: 0.0015`，`normal_bias: 0.02`，`shadow_extent: 40.0` |
| `Light::point(pos, color, intensity, range)` | `Point` | `Falloff::SmoothRange`，无阴影 |
| `Light::torch(pos, dir, color, intensity, range)` | `Spot` | `cos_inner: 0.85`，`cos_outer: 0.55`，投射阴影 |

`Light` 是一个字段公开、且**没有 `with_*` 构建器**的枚举：构造那个变体，或者对它
做 match。`Falloff` 是 `InverseSquare`（`1/(1+d²)`，追踪器的默认值）、
`SmoothRange`（`1 - (d/range)²`，光栅化器的默认值，因此光源可以被一次范围查询
排除）或 `None`。

`Scene::ambient` 是一个 `Ambient` { `sky`、`ground`、`hemisphere`、`intensity` }：
`default()` 是一对冷天空/暖地面的日光色，`night()` 和 `interior()` 是预设，
`radiance_at(normal)` 是逐法线项，`flat()` 是无方向项。

`Scene::fog` 是一个 `Option<Fog>` { `color`、`start`（40 m）、`end`（120 m）、
`height_falloff`（0 关闭高度雾）}；`factor_at(position, camera_position)` 基于
距离，`apply` 向雾色混合。雾也作用于无光照表面 —— 空气透视是场景的属性，而一张
手工绘制的精灵渐隐进远方正是像素风的样子。

## 调试叠加层

`noxel-render::overlay` 是绘图图元，不是 UI 工具包（`docs/adr/0009-no-ui.md`）。
它把所请求 sRGB 颜色的精确线性值写进**线性**帧缓冲，所以 `#FF0000` 解析回来仍是
`#FF0000`。

| 方法 | 绘制 |
|---|---|
| `text` / `text_scaled` | 内置 3x5 字体（`WIDTH` 3、`HEIGHT` 5，另加一列间距） |
| `line`、`screen_line`、`segment` | 世界线与屏幕线 |
| `aabb`、`ray`、`highlight_bounds` | 世界空间的盒线框与相机射线 |
| `cross`、`crosshair` | 标记 |
| `screen_rect`、`panel`、`stats_panel` | 面板 |

`set_depth_test(false)` 画在所有东西之上，这正是 HUD 想要的。
`RasterRenderer::debug_draw_tiles` 勾出每个非空瓦片箱的轮廓 —— 这是看分箱器是否
在工作的最快办法。字体是大写、大小写不敏感的，没有字形的字符（任何非 ASCII
码点）会被跳过、其单元格留空，而不是被截断或 panic；`'\n'` 是一个空白单元格且
不换行，所以每行调用一次 `text_scaled`。

## 常见错误

- **「我的精灵颜色不对。」** 有东西被照亮了：`Material::default()` 是无光照的，
  但结构体字面量或 `Material::lit` 不是。
- **「透明物体在其他透明物体后面消失。」** 该通道按*实例中心*排序，所以单个实例
  内部的层叠半透明无法交错；把它们拆成多个实例。
- **「阴影爬行、抖动或太贵。」** 纹素吸附被关了，或者 `shadow_extent` 远大于可见
  区域，于是每个纹素覆盖一大片世界。阴影痤疮（acne）说明 `shadow_bias` 太小。
- **「混合阴影是黑的。」** 它们应该是 0.35 的乘数；黑色阴影意味着是光栅阴影贴图
  产生的，所以 `RenderSettings::mode` 很可能不是 `Hybrid`。
- **「光线追踪模式下什么都看不见。」** `ray_budget` 在像素循环到达屏幕那一部分
  之前就用完了（它按行序推进并停止）。提高预算，或降低 `samples_per_pixel`。
- **「光线追踪的一帧发白或被截断。」** `App::resolve` 从这一帧实际渲染所用的模式
  推导色调曲线，所以这通常是 `RenderSettings::exposure` 对该场景不合适，而不是
  曲线缺失。用 `ShadingMode::Raytrace` 渲染的一帧会用 `ToneMap::Aces` resolve；
  运行时切换模式就够了，不需要额外配置。
- **「泛光不见了。」** `bloom_threshold` 和 `bloom_intensity` 都默认为 0，而阈值
  为 0 会把整幅图泛光，而不是只泛亮部。
- **「`Framebuffer::new` panic 了。」** 零尺寸的目标永远是 bug（通常是窗口最小化
  到 0x0）；构造函数选择断言，而不是悄悄产出一帧空图。

# 物理

`noxel-physics` 是一个固定时间步、确定性、安全 Rust 的刚体引擎，为俯视 RPG 调校：手感舒服的玩家移动、一镇子会安定下来而不是抖个不停的物件，以及可以逐位重放的结果。

## `PhysicsWorld` 生命周期

```rust
use noxel_core::math::{Aabb, Vec3};
use noxel_physics::{BodyDesc, ColliderShape, PhysicsConfig, PhysicsWorld};

let mut world = PhysicsWorld::new(PhysicsConfig::default());
world.insert_static_aabb(
    Aabb::new(Vec3::new(-10.0, -1.0, -10.0), Vec3::new(10.0, 0.0, 10.0)),
    0, // user_data, echoed back by query hits
);
let crate_ = world.insert(
    BodyDesc::dynamic(ColliderShape::Box { half_extents: Vec3::splat(0.5) })
        .at(Vec3::new(0.0, 4.0, 0.0)),
);

for _ in 0..240 {
    world.step(1.0 / 60.0); // dt clamped to `max_step_delta`
}
assert!((world.body(crate_).unwrap().position.y - 0.5).abs() < 0.01);
```

| 方法 | 说明 |
|---|---|
| `new(config)` | 配置会被净化（见调参表） |
| `insert(BodyDesc) -> BodyHandle` | 达到 `max_bodies`（4096）后返回 `BodyHandle::INVALID` —— 始终检查 `contains()` |
| `insert_static_aabb(Aabb, user_data)` | 把关卡碰撞转成物理几何的常用方式 |
| `remove(handle) -> bool` | 移除刚体、它的宽相条目、它的接触以及它的配对历史 |
| `clear()` | 移除一切并重置统计 |
| `body(handle)` / `body_mut(handle)` | `Option<&Body>` / `Option<&mut Body>` |
| `bodies()` | 所有存活刚体，按槽位顺序 —— 确定性的遍历顺序 |
| `set_position` / `set_rotation` / `set_velocity` | 做校验、唤醒刚体、立即刷新宽相 |
| `translate_kinematic(handle, delta)` | 移动一个运动学（或动态）刚体；拒绝静态刚体 |
| `set_gravity(Vec3)`, `step(dt)` | 非有限或非正的 `dt` 会被完全忽略 |
| `contacts()`、`events()`、`clear_events()`、`stats()`、`last_step_delta()` | 每步的读数 |

## `BodyDesc` 与 `BodyKind`

```rust
use noxel_core::math::{Quat, Vec3};
use noxel_physics::{BodyDesc, ColliderShape, LAYER_ALL, LAYER_PROP};

let desc = BodyDesc::dynamic(ColliderShape::Sphere { radius: 0.5 })
    .at(Vec3::new(1.0, 2.0, 3.0))
    .with_velocity(Vec3::X)
    .with_mass(2.0)
    .with_friction(0.4)
    .with_restitution(0.2)
    .with_damping(0.1, 0.2)
    .with_gravity_scale(1.0)
    .with_layer(LAYER_PROP, LAYER_ALL)
    .with_rotation(Quat::IDENTITY)
    .with_user_data(9);
let _ = desc;
```

| 构造器 | 默认值 | 效果 |
|---|---|---|
| `dynamic(shape)` / `static_body(shape)` / `kinematic(shape)` | — | 刚体种类（`static` 写作 `static_body`） |
| `at(Vec3)` | `Vec3::ZERO` | 世界坐标位置 |
| `with_rotation(Quat)` | 单位四元数 | 朝向；盒子会完整使用它 |
| `with_velocity` / `with_angular_velocity` | 零 | 初始速度 |
| `with_mass(f32)` | `volume * DEFAULT_DENSITY`（1 kg/m³），最小 1e-3 | 对静态和运动学刚体忽略 |
| `with_friction(f32)` | `0.5` | 库仑系数，钳制到 `[0, 1]` |
| `with_restitution(f32)` | `0.0` | 弹性，钳制到 `[0, 1]` |
| `with_damping(linear, angular)` | `0, 0` | 每秒的指数衰减 |
| `with_gravity_scale(f32)` | `1.0` | `0` 让刚体漂浮 |
| `with_layer(layer, mask)` | `LAYER_WORLD`、`LAYER_ALL` | |
| `with_user_data(u64)` | `0` | 由查询命中和接触回传 |
| `as_sensor()` | 关 | 上报重叠，但从不产生推力 |
| `sleeping(bool)` | 关 | 只有动态刚体才能真正休眠 |

`Body` 把这一切都以公开字段暴露出来（`position`、`rotation`、`linear_velocity`、`angular_velocity`、`mass`、`inv_mass`、`restitution`、`friction`、`linear_damping`、`angular_damping`、`gravity_scale`、`is_sensor`、`sleeping`、`sleep_timer`、`layer`、`mask`、`user_data`、`shape`），另外还有 `aabb()`、`is_dynamic()`/`is_static()`/`is_kinematic()`、`can_collide_with()`、`wake()` 和 `apply_impulse()`。

| `BodyKind` | 受重力 | 受冲量 | 被其他刚体推动 | 休眠 |
|---|---|---|---|---|
| `Dynamic` | 是 | 是 | 是 | 是 |
| `Static` | 否 | 否（`inv_mass` 为 0） | 否 | 从不 |
| `Kinematic` | 否 | 否 | 否 —— 它会推动动态刚体 | 从不 |

`BodyDesc::build` 在刚体存在之前就做净化：非有限的位置、速度或旋转会变成零/单位值，摩擦与弹性会被钳制，缺失或非正的质量则由形状的体积推导出来。

## 碰撞体：哪些形状是精确的

```rust
use noxel_core::math::Vec3;
use noxel_physics::ColliderShape;

let cube   = ColliderShape::Box { half_extents: Vec3::splat(0.5) };
let ball   = ColliderShape::Sphere { radius: 0.5 };
let person = ColliderShape::Capsule { radius: 0.3, half_height: 0.5 }; // along local Y
let barrel = ColliderShape::Cylinder { radius: 0.4, half_height: 0.6 };
let _ = (cube, ball, person, barrel);
```

形状定义在**它自身刚体的局部空间**中 —— 以刚体原点为中心，靠刚体的 `position` 和 `rotation` 放置。每种形状都有精确的 `aabb`、支撑函数、`contains_point` 和射线测试。窄相把每一对形状归约为一个最近特征对：

| 配对 | 方法 |
|---|---|
| 球 / 球 | 解析解 |
| 球 / 盒 | 盒子上的最近点，包括球心位于盒内的情况 |
| 球 / 胶囊 | 轴线段上的最近点 |
| 胶囊 / 胶囊 | 两条线段之间的最近点 |
| 胶囊 / 盒 | 线段与 AABB 之间的精确最近点 |
| 盒 / 盒 | 带最小平移向量的 15 轴 SAT |
| **任意 / 圆柱** | **圆柱被替换为它的局部包围盒**（`r`、`hh`、`r`） |

圆柱是唯一一处有文档记录的不精确之处：它为所有非球体配对保持一套一致的接触模型，代价是木桶在角落处的碰撞比它的网格稍宽一点。这一点要紧时请用胶囊或盒子。每对形状只生成一个接触点（盒/盒时取入射盒穿透顶点的质心），在这个尺度上足够了。

### 层与 `QueryFilter`

层是单个位，只有**双方**都同意时一对刚体才会碰撞：`(self.layer & other.mask) != 0 && (other.layer & self.mask) != 0`。单向的掩码是经典 bug —— 两个刚体不只是停止碰撞，它们会直接穿过地板掉下去。

| 常量 | 位 | | 常量 | 位 |
|---|---|---|---|---|
| `LAYER_WORLD` | `1 << 0` | | `LAYER_TRIGGER` | `1 << 4` |
| `LAYER_PLAYER` | `1 << 1` | | `LAYER_CAMERA` | `1 << 5` |
| `LAYER_NPC` | `1 << 2` | | `LAYER_ALL` | `u32::MAX` |
| `LAYER_PROP` | `1 << 3` | | | |

```rust
use noxel_physics::{QueryFilter, LAYER_NPC};

// `caster` is the handle of the body doing the querying.
let filter = QueryFilter::with_mask(LAYER_NPC).ignoring(caster);
let all = QueryFilter::ALL.with_sensors(false).with_static(true);
let _ = (filter, all);
```

`QueryFilter::default()` 能看到所有实心、非传感器的几何体，**包括**静态刚体 —— 刻意不用推导出来的全零值，那会拒绝一切，让视线射线直接穿过关卡。

## 一步的执行顺序

1. 恢复玩法代码留下的任何非有限状态，
2. 积分速度（重力 + 阻尼，仅对醒着的动态刚体），
3. 同步空间哈希并收集重叠配对，
4. 窄相：重建接触列表，
5. 求解速度（顺序冲量），
6. 积分位置（半隐式欧拉，使用求解器给出的速度），
7. 校正位置（Baumgarte 投影），
8. 唤醒被移动邻居碰到的刚体，然后更新休眠计时器，
9. 发出碰撞/触发/休眠事件，
10. 再做一次恢复，这样一步结束时不会留下任何非有限值。

一切都按槽位顺序遍历刚体槽位表，或者遍历句柄的 `BTreeSet`；这一步里没有任何地方遍历 `HashMap`。`dt` 会被钳制到 `max_step_delta`（0.05 s），所以一次卡顿无法让高速刚体穿墙瞬移过去。

## 求解器

不做热启动：每一步都重建接触集合、有效质量和弹性目标，然后跑 `solver_iterations`（4）次 Gauss-Seidel 扫描。

- 累积的法向冲量被钳制为非负。
- 累积的切向冲量被钳制在库仑锥 `|jt| <= mu * jn` 内；切向速度低于 `FRICTION_EPSILON`（1e-5 m/s）时完全不求解。
- **弹性只在超过 `RESTITUTION_THRESHOLD`（1.0 m/s）时生效。** 没有这道闸门，静止的刚体会永远在自己的数值噪声上弹跳。
- **接触只交换偏航角。** 一个板条箱永远不会因为某个角上的摩擦冲量而被掀翻。`angular_velocity` 的 X 和 Z 分量依然存在并且会被积分，所以玩法代码可以刻意让刚体翻滚 —— 只是接触从不会产生它们。
- Baumgarte 校正在速度扫描之后运行，使用 `position_correction`（0.2），每个接触的上限是 `MAX_CORRECTION`（0.2 m），这样深度重叠的一对刚体不会瞬移着分开。

**休眠**使用 `sleep_linear_threshold` 0.05 m/s、`sleep_angular_threshold` 0.05 rad/s 和 `sleep_time_required` 0.5 s；进入休眠时速度归零。休眠中的刚体表现得像不可移动，直到：

- 玩法代码调用了世界的 setter、`Body::wake()` 或 `Body::apply_impulse`（它们都会发出 `BodyWoke`），或者
- 一个**醒着的、非静态**的邻居碰到它，并且要么这次接触是这一步*新增*的，要么那个邻居在求解之后仍在移动。

正是这两个触发条件，既阻止静止的堆叠嗡嗡作响（它的接触持续存在，求解后的速度为零），又能捕捉到求解器已经吸收了冲击的抛射物，或者开始移动时就已经贴着休眠刚体的运动学平台。

## 角色控制器

`move_character(handle, desired_motion, up)` 扫掠刚体自身的碰撞体并移动刚体。`desired_motion` 是单位为米的**位移**（速度 × 帧时间），不是速度。

| 常量 | 值 | 含义 |
|---|---|---|
| `MAX_SLOPE_ANGLE` | 46° | 比这更陡就当作墙 |
| `STEP_HEIGHT` | 0.4 m | 角色能走上去的台阶高度 |
| `GROUND_SNAP_DISTANCE` | 0.2 m | 已经着地时向下寻找地面的距离 |
| `MAX_SLIDES` | 4 | 每次水平移动的滑面次数 |
| `STEP_PROGRESS_EPSILON` | 1e-3 m | 台阶式移动必须比直接移动多推进这么多才算数 |

1. **向上。** 向上的部分先扫掠，所以跳跃无法把角色推穿天花板（改为设置 `hit_ceiling`）。
2. **水平。** 水平部分被扫掠，并沿至多 `MAX_SLIDES` 个表面滑动。*可行走*表面沿其真实法线滑动，这会把角色抬上坡道；过陡的表面只抵消水平分量，因此爬不上去。如果直接移动被挡住，控制器会从高 `STEP_HEIGHT` 处重试再落回来；只有台阶式的结果严格推进更多时它才胜出，并且会先检查头顶空间。
3. **向下。** 向下的部分再加上一次贴地探测。非上升中的角色会在自身下方探测 `GROUND_SNAP_DISTANCE`，这让它牢牢贴住地板、楼梯和斜坡，也让刚生成的角色无需单独一帧的沉降就能报告 `grounded`。跳跃中的角色永远不会被拉回地面。

**平台承载：** 曾站在移动刚体上的角色会继承该刚体的位移（`velocity * last_step_delta`），但只在不是向上移动时。正是这一点让运动学平台能够载着玩家走。

`CharacterMove` 上报 `translation`（实际施加的位移）、`velocity`（`translation / last_step_delta()`，第一步之前为零）、`grounded`、`ground_normal`、`ground_body`、`hit_ceiling`、`hit_wall` 和 `hit_count`。

### 一个完整的控制器示例

```rust
use noxel_core::math::{Aabb, Vec3};
use noxel_physics::{BodyDesc, ColliderShape, LAYER_PLAYER, PhysicsConfig, PhysicsWorld};

let mut world = PhysicsWorld::new(PhysicsConfig::default());
world.insert_static_aabb(
    Aabb::new(Vec3::new(-30.0, -1.0, -30.0), Vec3::new(30.0, 0.0, 30.0)),
    0,
);
// Capsule centre 1.35 m up: radius 0.35 + half_height 1.0.
let player = world.insert(
    BodyDesc::kinematic(ColliderShape::Capsule { radius: 0.35, half_height: 1.0 })
        .at(Vec3::new(0.0, 1.35, 0.0))
        .with_layer(LAYER_PLAYER, u32::MAX),
);

let dt = 1.0 / 60.0;
world.step(dt);
let wish = Vec3::new(1.0, 0.0, 0.0) * 3.4 * dt; // displacement, not velocity
let moved = world.move_character(player, wish, Vec3::Y);
assert!(moved.translation.x > 0.0 && moved.grounded);
```

几句能省时间的说明：控制器是为 `BodyKind::Kinematic` 刚体准备的（它也能移动动态刚体，但之后求解器会为位置跟它打架）；请在 `step` **之后**调用它，这样 `last_step_delta()` 和承载都是最新的（`App` 反着来 —— 先更新玩法，再 `physics.step` —— 代价是 `velocity` 会滞后一帧，这没问题，但要保持一致）；使用的是刚体自身的 `shape`、`rotation`、`mask` 和 `layer`，传感器被忽略，刚体自身总被排除在外。

## 射线与重叠查询

```rust
use noxel_core::math::{Ray, Vec3};
use noxel_physics::{QueryFilter, RaycastHit};

let ray = Ray::new(Vec3::new(0.0, 10.0, 0.0), Vec3::DOWN);
if let Some(RaycastHit { body, distance, point, normal, user_data }) =
    world.raycast(&ray, QueryFilter::default())
{
    let _ = (body, distance, point, normal, user_data);
}
```

| 查询 | 返回 |
|---|---|
| `raycast(&Ray, QueryFilter)` | 最近的命中，或 `None`。方向会在内部归一化；从形状内部出发的射线报告距离 0，法线与射线方向相反 |
| `raycast_all(&Ray, QueryFilter, &mut Vec<RaycastHit>)` | 所有命中，先按距离再按句柄排序 |
| `overlap_sphere(center, radius, filter, &mut Vec<BodyHandle>)` | 所有重叠的刚体，按句柄排序；接触也算 |
| `overlap_aabb(bounds, filter, &mut Vec<BodyHandle>)` | 盒子的同上 |

每个查询都从空间哈希收集候选，然后对真实形状做**解析**测试，所以结果从不受宽相近似的限制；候选先按句柄排序，因此平手时的裁决每次运行都一致。形状扫掠是存在的（`sweep_shape`，保守推进），但属于 crate 私有 —— 公开的扫掠 API 就是角色控制器。

## 事件

`PhysicsEvent` 会一直累积，直到 `clear_events()`；你应该在消费它们的那个帧的末尾调用它：

| 变体 | 触发时机 |
|---|---|
| `CollisionEnter { a, b, point, normal, impulse }` | 两个实心刚体开始接触。`a` 是较小的句柄，`normal` 从 `a` 指向 `b`，`impulse` 是累积的法向冲量 —— 对音频或伤害来说是个很好的撞击强度信号 |
| `CollisionExit { a, b }` | 它们不再接触 |
| `TriggerEnter { trigger, other }` / `TriggerExit` | 传感器开始或停止重叠 |
| `BodySlept { body }` / `BodyWoke { body }` | 休眠状态转换 |

一对刚体的两个方向只上报一次，以规范的（较小、较大）句柄顺序为键。

## 确定性

刚体按槽位表的顺序访问，宽相配对和接触按句柄排序，上一帧的配对集合是 `BTreeSet` 而不是 `HashSet`。这一步里不读取任何墙上时钟。`determinism_is_bit_exact` 会把一个场景跑两遍并比较每个刚体的状态。

## 调参

`PhysicsConfig` 的默认值，以及 `sanitized()` 会把它们钳制到的范围：

| 字段 | 默认值 | 钳制范围 | 原因 |
|---|---|---|---|
| `gravity` | `(0, -19.62, 0)` | 非有限 → 零 | 刻意取地球的 2 倍：俯视 RPG 是一眼扫过去的，坠落都很短，所以物件该快速安定下来 |
| `broadphase_cell_size` | 4.0 m | 0.05 … 1024 | 接近典型的刚体尺寸；改动它会重建哈希 |
| `contact_tolerance` | 0.005 m | 0 … 0.5 | 一个小的正余量能阻止静止刚体在接触与分离之间闪烁 |
| `solver_iterations` | 4 | 1 … 64 | |
| `position_correction` | 0.2 | 0 … 1 | 越高重叠消解得越快，也会注入能量 |
| `max_step_delta` | 0.05 s | 1e-4 … 1.0 | 一次卡顿不能让刚体穿模 |
| `sleep_linear_threshold` | 0.05 m/s | 0 … 1e3 | |
| `sleep_angular_threshold` | 0.05 rad/s | 0 … 1e3 | |
| `sleep_time_required` | 0.5 s | 0 … 1e3 | |
| `max_bodies` | 4096 | ≥ 1 | 超过它 `insert` 会拒绝 |

## 常见错误

- **「我写了 `world.body_mut(h).unwrap().position = p`，什么都没动。」**（a）没有调用 `world.step(dt)` —— 没有它就没有任何积分。（b）刚体不是 `Dynamic`：静态和运动学刚体的 `inv_mass == 0`，所以重力和冲量都被忽略。（c）`insert` 因为达到 `max_bodies` 返回了 `BodyHandle::INVALID`，于是 `body_mut` 返回 `None`，之后的一切都是空操作。每次 insert 之后都要检查 `world.contains(h)`。
- **「我移动了一个刚体，射线检测还是打中旧位置。」** 通过 `body_mut` 写 `body.position` 不会刷新宽相；请用 `set_position`，它会刷新 —— 这正是 `queries_respect_change_after_set_position` 所断言的。
- **「两个刚体互相穿过。」** 掩码是单向的；两个刚体都必须列出对方的层。
- **「我的板条箱永远在抖，或者一摞箱子慢慢下沉。」** 对这个步长来说弹性太高（弹性只在超过 1 m/s 时生效），或者 `contact_tolerance` 是 0，而求解器迭代次数太少，斗不过重力。
- **「木桶在角落处碰撞得很怪。」** 圆柱按它的局部包围盒碰撞；需要圆润的形状请用胶囊。
- **「玩家能爬上 45° 的坡，却爬不上 50° 的，或者卡在路沿上。」** `MAX_SLOPE_ANGLE` 是 `to_radians(46.0)` 且为闭区间；高过 `STEP_HEIGHT`（0.4 m）的凸起按设计就是墙。
- **「玩家从移动平台上掉下去。」** 承载要求角色曾站在那个刚体上、且不是向上移动，并且用的是平台的 `linear_velocity * last_step_delta()` —— 用 `translate_kinematic` 移动的平台没有速度。
- **「事件每帧都在触发。」** 在读取它们的那个帧的末尾调用 `clear_events()`。
- **「把 `max_step_delta` 调高之后高速刚体穿模了。」** 钳制只是一张安全网：*求解器*是离散的，所以一步内移动超过自身厚度的刚体可以穿过薄几何体。

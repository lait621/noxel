# 实战笔记：在 Noxel 上做一个游戏

这里每一条都是花了代价换来的。尤其是——**它们中的大多数不会产生任何报错**，
这正是它们值得写下来的原因。开工前读，别卡住了才读。

---

## 坑

### 世界是隐形的

**现象。** 画面在渲染，HUD 正常，世界**正好**是背景色。`instance_count()` 是对的，
可见性剔除接受了每一个实例，没有任何地方报错。

**原因。** 四边形按 `(x0,z0) → (x1,z0) → (x1,z1)` 绕序时法线是 `-Y`。光栅器会剔除
背面，所以垂直向下的相机看到的是每一块地砖的**背面**。改成
`(x0,z0) → (x0,z1) → (x1,z1)` 法线朝上，一切就出现了。

**为什么这么费时间。** 剔除接受一个实例 ≠ 光栅器会画它。除了数像素，前面每一道
检查都会通过。

**怎么做。**

```rust
for index in 0..mesh.triangle_count() {
    assert!(mesh.triangle_normal(index).y > 0.5, "相机看到的是它的背面");
}
```

端到端则要断言**真正画出的像素**：

```rust
let lit = framebuffer.color_slice().chunks_exact(3).filter(|c| c[0] > 0.08).count();
assert!(lit > 10_000, "农场通过了剔除，但只画了 {lit} 个像素");
```

### 色调 `WHITE` 的意思是"按原作绘制"，不是"乘 1"

图集把覆盖率存在 alpha 里、RGB 全白。`blit` 特判了 `Color8::WHITE`，直接画原像素。
但九宫格的**拉伸**助手没有，它把色调当成了颜色——于是白色色调的边框画出来是**一块
白板**，而四个角（走 `blit`）却是对的。"白盒子配彩色边框"是非常具体的观感，它精确地
指向这个 bug。

加绘图助手时，先决定 `WHITE` 是什么意思，然后走同一个 `color_of` 函数，保证只有一个答案。

### 逐帧的标志位必须逐帧清

`UiState::modal` 由遮罩设置、由画它的界面降下。有五个界面在那个约定之前就画了遮罩，
从不降下。**玩家第一次打开背包，这个标志就立起来再也没下去**——而 `interact` 在标志
置位时拒绝 hover 任何东西，所以**从那一刻起游戏里每一个按钮都是死的**，而画面看起来
完全正常。

现在 `begin_frame` 会清它。规则：**如果一个标志位描述的是"这一帧"，那就由帧机制来清，
不是由设置它的代码来清。** 对照 `pointer_over_ui`、`hot`、`consumed_click`——都在
`begin_frame` 里清，同一个理由。

### 屏幕空间的效应用不了相机

雨画成屏幕上随机位置的划线：相机一动它不动、没有纵深、永远不落地。二十行代码，
永远错在同一件事上，而描述永远是"看起来就是在屏幕上播动画"。

任何**存在于世界里**的东西——雨、手持工具、高亮框——都必须在世界空间模拟，
绘制时用渲染器自己的算式投影。

### "会不会被遮挡"是一个必须主动做的选择，选错就是 bug

高亮框**必须**画在 UI 层：世界精灵需要一个"恰好比被高亮的东西高一点点"的深度，
这个搞错就会让光标消失在土豆后面。

手持工具**必须**画在世界层：画在 UI 层它就在每棵树、每栋建筑、以及你正瞄准的那一格
之上，收到的反馈就是"工具挡视野"。

没有通用答案。只有"这个东西**应该**能被什么挡住？"——每个东西问一次。

### `match` 里那个"猜"的 `_` 分支

```rust
let atlas = match which {
    "terrain" => ...,
    "crops" => ...,
    "characters" => ...,
    _ => assets.atlases.props.as_ref(),   // <- "ui" 落到了这里
};
```

漏一个分支不会失败。它会在正确的坐标上采样**错误的图**，于是手持的锄头画出来
像一只木箱。当一个兜底分支是"看起来也说得通"而不是"明显是错的"，它一定会被命中，
而且一定静默。

### 打包脚本会和目录树脱节

一个打包脚本还指向 `games/noxel-valley/assets`——那是它住在上一层目录时的路径。
该路径不存在，于是"资源缺失就生成"那个分支**把它创建了出来**，里面只有精灵、没有字体，
每个发行包都是从那个野生目录打出来的。游戏能跑、能响应输入、**没有一个字**。

修复不是那个路径。修复是脚本现在会**断言**每个必需文件存在，并在打包后验证二进制
真的能找到字体。只警告不够：这个故障看起来像"游戏坏了"，而不是"少了个文件"。

### 同一个 crate 的两份拷贝

游戏用 `git` 版本依赖引擎、同时又用 `path` 依赖一个新引擎 crate，就会拿到**两个**
`noxel-core`，因此有两个结构完全相同但**不能互相赋值**的 `Vec3`。
报错是 `expected Vec3, found Vec3`，要困惑十分钟。

引擎和游戏一起改的时候，**所有**依赖指向同一边。绝不要混。

### 测试全绿，游戏不能玩

所有 UI 测试都从"输入转换之后、帧循环之内"开始。于是"每个按钮都按不动"的 bug
在一个全绿的测试套件后面躺了三轮，而反馈是"按钮不工作"。

真正有用的测试走真实路径：

```rust
valley.borrow_mut().input = ui_input(&window_input((x, y)));
app.step(1.0 / 60.0);
```

并且断言玩家能感知的结果——界面变了、钱少了。开始菜单一个，商店的"买"按钮一个，
后者是**扫遍整屏**找到的，而不是相信一个布局常量。

### 资源在你检查之前都不算提交了

`--check` 存在的理由：确定性的生成器跑两遍也可能和**已提交的东西**不一样。
美术生成器刚搬进游戏仓库时，提交的 PNG 相对最终代码是旧的——JSON 对得上（所以每个
区域名字和尺寸都对），三个 PNG 对不上。**名字和尺寸对，不等于像素对。**

## 技巧

### 投影，以及只用这一个投影

一个世界单位 = 一格 = `TILE` 个像素，相机焦点是画面中心：

```rust
let centre_x = (world.x - focus.x) * TILE + width  / 2;
let centre_y = (world.z - focus.z) * TILE + height / 2;
```

**写一次**，写成函数，所有需要落在格子上的东西都用它：高亮框、天气、手持物品、生成标记。
每一个自己推导一份的调用点都会漂移，而漂移在屏幕中央看不出来、在边缘一眼就看出。

**用相机的 `snapped_focus()` 投影，绝不用玩家位置。** 相机做平滑并吸附到 1/16 格，
走路时两者最多差半格——那正好就是"高亮框和它该指的那一格之间的偏移"。这是真实反馈。

### 不用排序的深度

一切都是地面平面上的扁平四边形。垂直向下的相机下，世界 `z` **就是**屏幕深度——
给每个四边形一个正比于 `z` 的极小 `y` 偏移，深度缓冲自己就排好了：

```rust
const DEPTH_STEP: f32 = 0.001;
fn depth_of(z: f32) -> f32 { DEPTH_STEP * (z + 1.0) }
```

比玩家靠前两千分之一个单位的手持物品，读起来就是"拿在手上"而不是"站在旁边"。
玩家南边的树 `z` 更大，就会挡住它后面的东西。

### 纯整数布局：测量，别猜

界面里每一条糊边都来自一个"对另一种字体、另一个字号、另一种语言才成立"的布局常量。

* 行距是 `font.measure("操作", &style).1`，不是 `11`。
* 标题高度要测：scale 2 的中文标题 24 像素、拉丁 18 像素，给两者都留 14 就会把标题
  画穿第一行。
* 面板宽度跟着内容走。三个面板写死了宽度，字体一大 17% 就溢出，修法是别再写死。
* `.round()`，不要截断。小数坐标就是"相机一动、高亮框抖一个像素"。

还有一条很痛的：`FontSet::measure` 和 `FontSet::draw` 对**未知字符**必须给出一致的宽度，
否则一个字符串量出来的宽度和画出来的不一样。

### 一行文字，一次绘制

`FontSet::draw_text` 把一行对齐到**这一行用到的字面**的基线。纯拉丁一行和中文一行画在
同一个 `y` 上**不共享基线**：中文更高，所以坐得更低。混排内容分行放，否则看起来就是
"同一行的两种字号"。

（底层规则是：字形的偏移从**它自己字面的**基线量起，渲染器再按
`line_baseline - face_baseline` 平移。把基线算了两遍，拉丁就会比旁边的中文低六个像素。）

### 传数据，不传回调

界面没理由读农场，农场也不需要知道提示怎么画。游戏算出一句话递过去：

```rust
self.game_ui.set_hint(screens::hint(&self.state, &self.map, &self.player));
```

这让"上下文教程"这个完整功能不必把一个 `&FarmMap` 穿过九个绘制调用，也让提示可以在
没有帧的情况下被测试。当你想往 `Ui::draw` 里加一个新的借用时，改成传值。

### 无状态的确定性散布

粒子与装饰通常既要随机排布又要没有记账。两个互质步长乘计数器就够了：

```rust
let seed = index as f32 * 37.7;
let x = (seed * 7.3).fract() * width;
let y = (seed * 3.1 + phase * speed).fract() * height;
```

没有状态、没有分配，同一帧画两次是同一张图——这正是录像能重放、测试能对缓冲区断言的原因。

### 验证

这一节值得读两遍。

**测玩家走的那条路，不是方便测的那条。** 从输入转换之后开始的测试，找不到输入转换里的
bug；从帧循环之后开始的测试，找不到帧循环里的 bug。

**断言一个"人"能感知的东西。** "网格有顶点"在世界隐形时也通过。"实例被剔除接受了"
在每个三角形都被拒绝时也通过。"按钮上报了点击"在点击处理根本没走到时也通过。
数像素、比金币、看当前是哪个界面。

**每个修复配一个"去掉它就变红"的测试。** 不是"套件还是绿的"，而是：把修复回滚，
看着新测试变红，再放回去。如果它红不了，说明你没搞懂这个 bug，那个测试只是装饰。

**只缓解症状的修复不是修复。** 手持工具被反馈"挡视野"；它被改小了、留在同一层，
然后又被反馈了一次。第二次反馈是对的，第一次"修复"是一种不去理解第一次反馈的方式。

**有人说"X 不工作"时，去找他看到的东西，不是代码做的事。** "买了种子种不了地"不是
购买的问题——是选中种子后手上变成 `Tool::Hand`，而田地初始是未翻的土，且**没有任何
地方说过"缺翻土这一步"**。代码是对的，游戏是不能玩的。

**看数字的含义。** `1704 passed, 0 failed` 不是"游戏能用"的证据，是"代码做了测试说的事"
的证据。这是两个不同的断言，而这份文档里每一个 bug 都住在它们的缝隙里。

### 资源

* **生成，不要手画。** 两个生成器都是确定性的：跑两遍不改变任何字节，所以 `assets/`
  出现 diff 就意味着真的变了。
* **`--check` 不是可选项。** 它重新生成到临时目录做逐字节比较。提交美术前跑一次。
* **绝不手改生成出来的文件。** 改生成器。
* **1-bit 字体必须超采样。** 4 倍带抗锯齿光栅化 → 按精确面积做盒式降采样 → **再**二值化。
  中间那一步才是修复：带 hinting 的光栅器在 12px 下把笔画吸附到半像素上、按 40%
  覆盖率绘制，这个覆盖率在任何"能保住字形其余部分"的阈值下都会死掉。先平均测的是
  **真实覆盖率**，同一笔画这时到达 60%，活下来了。
* **平均之后，提高阈值是在侵蚀字形**，因为覆盖率被摊到了像素边界上。这和直接渲染时
  的行为相反，它把搜索方向整个反了过来。
* **烘焙完要看。** 把难字渲染出来、按整数倍最近邻放大、用眼睛看。数字不会告诉你
  日 和 曰 画成了一模一样。

### 特性与依赖

* 一切可选的东西都是**feature**，默认关闭，这样 `cargo build` 不下载任何东西。
* **一个 feature 蕴含另一个，必须写出来。** 游戏的 `window` 拉进了 `noxel-audio` 但没开
  它的 `output`，于是所有 `#[cfg(feature = "audio")]` 块被编译掉了——包括启动音频流的
  那个、以及告诉音乐总监天气的那个。什么都没失败，代码就是不存在。
* **`cargo build` 成功不是"某条代码路径存在"的证据。**

## 工作的形状

如果让你在这个引擎上做点能玩的东西，这套顺序是管用的：

1. **先让一样东西出现在屏幕上。** 一块地面、一个相机、一帧导出。在别的东西存在之前，
   先证明世界画得出来。
2. **把投影函数写出来并测掉。** 一切都依赖它，而且做对它很便宜。
3. **在做漂亮之前先把规则做成可测的。** `action::use_tool` 被从二进制里挪进库，
   就是为了让种田循环能在没有窗口的情况下被测试——那个测试立刻抓出了两个平衡问题。
4. **然后才是界面。** 它是最容易迭代、也最难做对的部分，而且**所有反馈都会落在它身上**。
5. **用真实构建、拿鼠标玩一遍。** 没有替代品。这份文档第一节里的每一个 bug 都是
   有人在**用**这个东西时发现的，不是测试发现的。

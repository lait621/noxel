# town-demo

一个完整的 Noxel 游戏循环，六个源文件：从种子生成世界、在其中长出一个村庄、把玩家放进广场、让街道挤满人群、用俯视相机跟随玩家，并把每一帧写成 PNG。

> **状态。** 下面的一切都已接通且全绿：`cargo test -p town-demo` 通过 56 个测试，
> `cargo clippy -p town-demo --all-targets -- -D warnings` 干净，
> `./scripts/build-dist.sh` 产出可整体搬迁的 `dist/`，无需源码树、无需工具链即可运行。
> 有意缺席的部分见文末「已知缺口」。

## 它演示了什么

| 系统 | demo 用它做了什么 |
|---|---|
| 世界生成 | 从种子构造 `WorldConfig`，在玩家周围流式加载；生物群系、道路、城镇与杂物都来自 `noxel-world` |
| 区块流式加载 | 每帧一次 `WorldStreamer::update`，由相机焦点驱动 |
| 地形网格化 | `TerrainPlugin`：每个区块一张网格，每个图块一个地面四边形，每个图块一个来自地形图集的 UV 区域 |
| 村庄网格化 | `village.rs` 把一个区块的建筑与杂物变成几何：每栋建筑一个带屋顶四边形的盒子，每棵树一个锥体，每块石头一个盒子——全部放在每个区块额外的两张网格里，因此一个区块是三次绘制调用 |
| 材质 | 地面**不受光**（美术的图块颜色得以保留），建筑与杂物**受光**，因此太阳与混合模式的光线追踪 AO 赋予它们体积感 |
| 碰撞 | 每个 `Chunk::colliders` 盒都变成一个静态物理体，随区块流式加载而增删 |
| 角色控制器 | 玩家是一个由 `PhysicsWorld::move_character` 移动的运动学胶囊：上台阶、贴墙滑动与坡度限制 |
| 相机 | 带死区、前瞻、平滑与裁剪平面的 `TopDownCamera` |
| 人群 | `NpcSystem`，每个 agent 一个场景实例，分层使得远处的 agent 不成为遮挡物 |
| 光照 | 环境天空/地面光、一个低角度太阳，以及线性距离雾 |
| 调试输出 | `noxel-debug` 中的计数器与区段预算、一份最终报告，以及 PNG 转储 |

## 命令

```bash
export PATH="$HOME/.cargo/bin:$PATH"

cargo run -p town-demo -- --frames 300 --dump frames
cargo run -p town-demo -- --mode hybrid --npcs 400
cargo run -p town-demo -- --stats            # one settled frame, full statistics
cargo run -p town-demo -- --world-info       # what this seed generates, no rendering
cargo run -p town-demo -- --help
```

| 标志 | 默认值 | 含义 |
|---|---|---|
| `--seed N` | `0x4E4F5845` | 世界种子 |
| `--frames N` | 600 | 模拟并渲染的帧数 |
| `--size WxH` | `320x180` | 内部分辨率 |
| `--mode MODE` | `raster` | `raster`、`hybrid`、`raytrace`（外加 `rasterize`、`rt`） |
| `--npcs N` | 240 | 目标人群规模 |
| `--dump DIR` | `frames` | 把每一帧作为 PNG 写到这个目录 |
| `--no-dump` | — | 渲染但不写任何东西 |
| `--stats` | — | 渲染一帧、打印其统计、退出 |
| `--world-info` | — | 打印该种子下世界的形状，退出 |
| `-q`、`--quiet` | — | 只输出摘要 |
| `-h`、`--help` | — | 用法说明块 |

从仓库根目录运行它：demo 先找 `examples/town-demo/assets`，再找 `assets/`。
那棵树**存在**且是生成的——不要手工编辑它。它附带一套 24 色调色板、四张纹理
（terrain、buildings、characters、props）、十二个预制体（`house_small`、`house_large`、`inn`、`barn`、
`shop`、`market_stall`、`well`、`lamp`、`tree_oak`、`tree_pine`、`fence_segment`、
`rock_cluster`）、一套 tile set 与 `world/demo.json`：

```bash
cargo run -p noxel-gen -- generate --force   # rewrite the whole tree
cargo run -p noxel-gen -- verify             # check it against the generator
cargo run -p noxel-gen -- preview            # contact sheet of the textures
```

`--world-info` 打印区块尺寸、视野距离、道路与城镇间距、已加载区块数量、五个
高度/生物群系/道路采样，以及原点附近的城镇及其地块数量。它会生成并流式加载，
但从不渲染。

## 你应该看到什么

`--frames 300 --dump frames` 写出 `frames/frame_000000.png` 及其后，320x180，
每个渲染帧一个文件，前面有 12 帧预热，因此第一张图就是稳定后的。终端打印一个
头部、一行 `HeadlessReport::summary()`，以及运行结束报告：帧数与 fps（均值与 p95）、
带 `last / allowance` 与 `ok`/`OVER` 的区段预算、每一个记录在案的计数器（区块数、区块
生成、区块内存、剔除计数、玩家位置、着地状态），
以及一个「下一步」块。

在图像里你应该看到：

- **平坦、不受光的地形**，位于 1 m 的图块网格上，屏幕上横跨 20 m 世界，
  纹理来自地形图集。地形不受光是刻意的：受光表面会把美术的图块颜色
  乘以太阳光。深度线索来自建筑、杂物，以及混合模式下的光线追踪 AO。
- **每 256 m 一张道路网格**，三图块宽并融入地形，
  以及最近城镇网格单元周围的村庄：一个广场、一个主十字、侧向
  街道，以及来自预制体库、带山墙屋顶与受光面的建筑。
- **杂物**——树、石头、栅栏——从不在路上、不在水里、不在陡坡上，
  也不在建筑内部。
- **一个胶囊玩家**沿环形脚本路线行走，在每个
  航点短暂停留，相机尾随其后。
- **一群胶囊**在广场周围填充，按类别着色。
- **距离雾**从 70 m 开始，到 160 m 完全遮蔽。

`--mode hybrid` 增加光线追踪的太阳阴影与环境光遮蔽；`--mode
raytrace` 追踪一切，是为静帧而非帧率准备的。

## `src/` 的逐文件地图

| 文件 | 行数 | 职责 |
|---|---|---|
| `main.rs` | ~300 | 参数处理、`App` 构造、世界/光照/相机设置、插件注册、运行循环、world-info 打印 |
| `args.rs` | ~280 | 手写的标志解析器、`world_config()`、`physics_config()` 与帮助文本 |
| `terrain.rs` | ~550 | `TerrainPlugin`：区块 → 地面网格、区块 → 静态碰撞体，随区块流式加载增删；`build_chunk_mesh`、`uv_rect`、`ground_height`、`is_walkable`、`sample_ground` |
| `village.rs` | ~360 | 区块 → 建筑与杂物网格，各一张网格，来自生成器合并后的盒体；受光材质 |
| `actors.rs` | ~630 | `Player`/`PlayerPlugin`（路线或输入、`move_character`、相机焦点）、`CrowdPlugin`（人群步进、按类别做场景镜像、层级标志），以及三个 `Plugin` 实现 |
| `hud.rs` | ~250 | 叠加层文本、遮挡物可视化器、最终报告与一行状态 |

### 三个插件如何串起来

`main.rs` 按这个顺序注册它们，而这个顺序就是契约：

```text
app.add_plugin(TerrainPlugin::new());   // 1. world geometry, after streaming
app.add_plugin(PlayerPlugin::new());    // 2. spawn the player, build the route
app.add_plugin(CrowdPlugin::new(cfg));  // 3. populate and step the crowd
```

`Plugin::build` 每个插件运行一次，按注册顺序。真正的顺序活在逐帧钩子里：

| 插件 | 钩子 | 原因 |
|---|---|---|
| `PlayerPlugin` | `update`（固定步长） | `move_character` 与其他一切一起以 60 Hz 运行；相机焦点在这里写入 |
| `PlayerPlugin` | `pre_cull` | 在引擎自己的 `frame_update` 移动相机并剔除之前，让焦点先定型 |
| `CrowdPlugin` | `update`（固定步长） | 等到 `streamer.stats().loaded > 0`，然后填充一次，并以 `app.context.elapsed` 作为 `world_time` 步进人群 |
| `TerrainPlugin` | `frame` | 在 `App::frame_update` 完成区块流式加载*之后*同步区块网格与静态体，因此几何与本帧驻留的内容一致 |

真正重要的链条是：**地形拥有几何与静态体，玩家拥有相机焦点，人群拥有其余一切。**
`App` 自己运行相机跟随、流式加载与可见性，在每个插件的 `update` 之后、
以及 `pre_cull` 钩子之后。

## 把它变成真正的游戏

有三件事是缺失的，且刻意超出引擎范围
（`docs/adr/0009-no-ui.md`、`docs/adr/0002-no-dependencies.md`）。

### 1. 接入窗口

Noxel 没有窗口层。`App` 产出 `Framebuffer` 并消费
`InputState`；呈现缓冲区是宿主的职责：

```rust,no_run
// Behind a feature flag, with `winit` or `SDL2` as an optional dependency.
loop {
    for event in window_events() {
        match event {
            Event::KeyDown(code) => app.input_mut().press(code),
            Event::KeyUp(code) => app.input_mut().release(code),
            Event::Resize(..) => { /* rebuild the presenter, not the app */ }
            Event::Close => break,
        }
    }
    app.step(frame_dt);              // fixed updates, camera, streaming, cull, render, overlays
    let image = app.resolve();       // linear HDR -> sRGB, once per frame
    present(image);                  // `Viewport::pixel_art` gives the integer scale
}
```

`app.step(dt)` 已经调用了 `InputState::end_frame()`，因此 `was_pressed`、
`was_released` 与鼠标增量都是单帧值。不要自己调用它。

### 2. 喂 `InputState`

`InputState` 是普通数据：`press(key)`、`release(key)`、`is_held`、
`was_pressed`、`was_released`、`movement_axis(up, down, left, right)`，外加
`mouse`、`mouse_delta`、`scroll` 与 `mouse_buttons`。键码由宿主决定——
demo 的自由移动分支把 WASD 读作 `82, 81, 80, 79`，
那是宿主码，不是引擎常量。`InputState::release_all()` 是为失焦准备的；
没有它，窗口失焦时按住的键会一直保持按下。

### 3. 替换脚本化路线

`PlayerPlugin` 有两种移动模式。脚本化的那种跟随
`PlayerPlugin::route`，一个由 `build_route` 构建的 `Vec<Waypoint>`，它绕一个
中心点走一圈，并把每个候选点向内推，直到
`TerrainPlugin::is_walkable` 接受它。这正是无头运行可复现的原因：没有输入、
没有随机性，每次都是同样的一段行走。插件实现传入
`scripted = true`，并有一条注释说明填充
`app.input_mut()` 的宿主可以把它翻过来——那是第一行要改的地方。

在那之后：为跳跃加上垂直速度（`Player::vertical_velocity`
存在，且未被脚本化分支使用），给人群真正的日程而不是占位村民，
并加一个 UI 插件，在 `draw` 钩子里用
`noxel_render::overlay` 绘制——或者带上你自己的 UI 库。

## 已知缺口

这些都是刻意的，每一个都有理由。

- **相机是固定的四分之三视角。** 真正的游戏想要缩放与
  旋转控制；`TopDownCamera` 两者都支持（`zoom_by`、`set_yaw`），它们被略去
  是为了让 demo 的脚本化路线逐帧可复现。
- **玩家沿脚本化的环形路线行走。** 没有窗口，因此没有
  输入流。`PlayerPlugin::update` 已经会在其
  `scripted` 标志为 false 时读取 WASD；等宿主开始填充 `app.input_mut()` 后把它翻过来。
- **NPC 不是从角色图集绘制的。** demo 给每个 agent 一张
  纯色广告牌；`assets/textures/characters.png` 里生成的 4 方向行走循环由
  `assets/sprites/characters.json` 描述，它在等待一个精灵批处理渲染器，
  而引擎目前还没有。
- **`frames/` 是一个临时目录。** demo 每帧写一张 PNG，并在启动时
  清除陈旧帧，但它从不清理当前这次运行。它被
  `.gitignore` 忽略。
- **很大的 `--npcs` 值受物理限制。** 靠近相机的第 0 层 agent
  拥有一个胶囊；其余只做转向与路径跟随。把人口提到几千以上，
  只是让更多人群进入更便宜的层级，而不会让帧变慢，这是
  预期行为，但从标志名上看不出来。

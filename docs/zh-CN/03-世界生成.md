# 世界生成

`noxel-world` 把一个种子变成地形、生物群系、道路、城镇、道具（prop），以及引擎其余部分所消费的碰撞数据。

**唯一的规则：** 区块是 `(config.seed, chunk_pos)` 的纯函数
（`docs/adr/0006-deterministic-generation.md`）。生成路径上没有任何东西持有可变的
RNG —— 每个阶段都从自己可寻址的流中取数
（`RngStream::for_chunk(seed, label, x, y)`）—— 所以区块 `(900, -400)` 无论是先生成、
后生成，还是在另一台机器上生成，都逐字节相同，并且区块可以并行生成，不必等待邻居。

## 地形

`WorldGenerator::sample_height(x, z)` 组合三个噪声场（常量位于
`crates/noxel-world/src/gen.rs` 顶部）：

| 阶段 | 噪声 | 频率 | 贡献 |
|---|---|---|---|
| 大陆遮罩 | `fbm_2d`，4 个倍频 | 0.00085（约 1200 m） | 海洋/海岸/内陆，经 `smoothstep(-0.30, 0.35, continent)` |
| 起伏 | `warped_fbm_2d`，5 个倍频 | 0.0035（约 285 m） | 海湾与半岛；由 `height_scale` 以及陆地的多少来缩放 |
| 山脉 | `ridged_2d`，5 个倍频 | 0.0018（约 550 m） | 山脉，由 `smoothstep(0.55, 0.92, ridge * (0.55 + 0.45 * land))` 门控 |

陆地项是一个带符号的偏移（`(land - 0.5) * scale * 0.9`），它把真正的海洋放到水位线
*以下*，而不只是让它偏低。随后有两个阶段修改高度场：**道路整平**
（`carve_roads` —— 在铺装宽度内保持平坦，外加两格路肩，且永不低于
`sea_level + 0.15 * tile_size`，因此穿过湖泊的道路会变成堤道）与**城镇压平**
（`flatten_towns` —— 城镇圆盘内侧 55% 的区域，用
`smoothstep(radius * 0.55, radius, distance)` 向广场拉平）。广场高度使用基础高度场
加上道路开挖，绝不使用压平结果，因此不存在递归。

`sample_slope(x, z)` 是对 `sample_height` 在一格跨度上的中心差分，所以
`atan(slope)` 就是地面倾角。`Chunk::heights`/`slopes` 与两者在舍入误差内一致
（`chunk_heights_match_sample_height_at_tile_centres`）。阈值：
`ROCK_SLOPE` 0.55（约 29°，超过即视为岩石）和 `MAX_PROP_SLOPE` 0.84
（约 40°，超过则不放置任何道具）。

## 生物群系

`biome_for` 按以下顺序从 `biome.rs` 中固定的八项表里选择：

| 判定 | 结果 |
|---|---|
| `height < sea_level` | `LAKE` |
| `height - sea_level > 1.15 * height_scale` | `MOUNTAINS` |
| `temperature < 0.30` | `TUNDRA` |
| `height - sea_level > 0.5 * height_scale` | `HILLS` |
| `moisture > 0.66 && temperature > 0.45` | `SWAMP` |
| `temperature > 0.70 && moisture < 0.42` | `DESERT` |
| `moisture > 0.52` | `FOREST` |
| 其他情况 | `PLAINS` |

温度是低频 fBm 加一个梯度（`+Z` 方向更冷）：
`smoothstep(-1, 1, 1.7 * noise - z * 0.00002)`；湿度是
`smoothstep(-1, 1, 1.5 * noise)`。id 是稳定的 —— `PLAINS` 永远是 `0`，`LAKE`
永远是 `7` —— 所以在存档里存 id；`Biome` 的每个字段都是公开的，因此游戏可以发布
一张改过的表。`Biome::height_bias` 只是给工具用的元数据：把它喂回高度场，会让高度
依赖于一个依赖高度的生物群系。

| 生物群系 | 基础瓦片（tile） | 点缀 | 树木密度 | 岩石密度 |
|---|---|---|---|---|
| `PLAINS` | `grass` | `grass_tuft` | 0.02 | 0.004 |
| `FOREST` | `grass_dark` | `moss` | 0.14 | 0.006 |
| `DESERT` | `sand` | `sand_rock` | 0.002 | 0.02 |
| `TUNDRA` | `snow` | `ice` | 0.012 | 0.03 |
| `SWAMP` | `marsh` | `reeds` | 0.07 | 0.002 |
| `HILLS` | `grass_rocky` | `stone` | 0.04 | 0.08 |
| `MOUNTAINS` | `stone` | `scree` | 0.004 | 0.12 |
| `LAKE` | `water` | `water_deep` | 0.0 | 0.0 |

## 瓦片与回退顺序

`tile_for` 在每个瓦片中心按以下优先级选出一个瓦片：水、道路、建筑地板、
岩石、沙滩沙地、点缀、生物群系基础。因此道路能在岸线处存活，而建筑的室内地板
只在没有更重要的东西时才出现。

每个瓦片*名称*都在 `WorldGenerator::new` 中解析**一次**，走一条有文档记录的回退链
—— 这正是空瓦片集仍能生成合法世界而不 panic 的原因：

1. 该名称或它的某个别名（水槽位对应 `water`、`deep_water`、`lake`、`ocean`、
   `sea`）；
2. 第一个带匹配标志的瓦片（`water`、`road`、`walkable`、`buildable`、
   `blocks_sight`）；
3. `grass`、`dirt`、`floor`、`stone`、`sand`、`water` 之一；
4. 瓦片集的第一个瓦片，然后是瓦片 id `0`。

完全空的瓦片集会把每个槽位都塌缩到 `0`。点缀瓦片由两个 `value_2d` 尺度
（0.09 与 0.45）选出，所以点缀会成片聚成草甸，而不是均匀地散成小点。

## 宏观道路格网

一条道路沿每第 `road_grid_chunks` 个区块边界延伸（8 个区块 = 256 m），并沿边界按
`RngStream::for_chunk(seed, "road/jitter", index, axis)` 抽出的抖动偏移。这个格网
**在构造上就是连通的**：每条纵向道路都穿过每条横向道路，所以整个网络是一张单一
图，生成时无需寻路。`RoadNetwork::generate` 把某个区域触及的线具体化，并向区域外
多延伸一格，使该区域被完整的道路穿过。

同一格网也有闭式表达，这正是地形能在不先构建线段列表的情况下开挖道路的原因：
`macro_line_x`、`macro_line_z`、`macro_spacing`、`nearest_line_index`
（做了钳制，因此巨大的坐标不会让 `i32` 溢出）以及 `road_jitter`。

`RoadSegment` 是共享的通货；`clip_to_aabb` 只把穿过某个区块的那一段交给它，因此
相邻区块绝不会重复报告同一段路面。`RoadNetwork::MAX_SEGMENTS`（200 000）为一个
大陆尺度的请求设了上限。

## 城镇

每个第 `town_spacing_chunks` 个区块格点位置都有一个城镇（默认 10），建成区半径为
`town_radius_chunks`（3）。这个格点是位置的纯函数，所以高度场、瓦片阶段和规划对
街道位置的看法一致：

```rust
use noxel_world::WorldConfig;
use noxel_world::town::{nearest_town_cell, town_centre};

let config = WorldConfig::new(4);
let cell = nearest_town_cell(&config, 340.0, -12.0);
let centre = town_centre(&config, cell); // y is 0; fill it from the height field
```

`TownStyle` 以固定权重抽取（hamlet 0.30、village 0.35、town 0.20、
crossroads 0.15），并缩放件数、街道和地块间距：

| 风格 | `building_density` | `building_scale` | `side_streets` | 地块间距（瓦片） |
|---|---|---|---|---|
| `Hamlet` | 0.35 | 0.4 | 0 | 1.44 |
| `Village` | 0.55 | 0.7 | 1 | 1.12 |
| `Town` | 0.80 | 1.0 | 3 | 0.72 |
| `Crossroads` | 0.65 | 0.85 | 1 | 0.96 |

间距是 `lerp_f32(2.0, 0.4, building_density())`：小村的地块之间留着近两格菜园，
城镇的地块几乎相接。

`TownPlan::generate` 布置穿过广场的主十字、每轴 `side_streets` 条街道（用
`sqrt(r² - offset²)` 裁剪到圆盘内）、一条通向最近宏观道路的连接路，以及每条街道
两侧的地块。如果一个地块越出圆盘、与广场重叠（`plaza_radius` 为 0.35 区块）、与
某条街道的 AABB 相交，或与已有地块的距离小于四分之一瓦片，它就会被拒绝。地块会
多预留四分之一：`buildings_per_town`（18）按风格缩放后是**建成**的数量，其余以
`taken == false` 留给游戏（`TownPlan::free_plots()`）。`buildings_per_town = 0`
仍会产生八个预留地块。

`TownPlan::instantiate` 把每个已占用地块变成一个 `BuildingInstance`：有能放下的
预制件（prefab）时就用预制件（优先标签 `building`/`house`，其次是旋转到地块朝向
后、能放进地块减去一格边距的最大占位），否则使用程序化回退 —— 一个带山墙屋顶的
实心盒子，两到四层高，名为 `PROCEDURAL_PREFAB`（`"procedural_house"`）。没有标签
且体积 < 4 的预制件绝不会被用作建筑；空的预制件库会用回退填满每个地块，所以城镇
绝不会是一片空地。建筑站在其地块上的*最高*地面采样点上，因此绝不会被埋进斜坡。

## 道具

树木和岩石按每瓦片一次掷骰从
`RngStream::for_chunk(seed, "chunk/props", x, y)` 撒出。每瓦片概率是
`prop_density * biome_density * 10.0`，钳制到 `[0, 1]`，树木用生物群系的树木密度，
岩石用其岩石密度。只要满足以下**任一**条件，道具就被拒绝（由
`props_respect_their_rejection_rules` 断言）：

| 规则 | 原因 |
|---|---|
| `height < sea_level` | 水里不长树 |
| `slope > MAX_PROP_SLOPE`（0.84） | 崖面上什么都不长 |
| 该瓦片是道路槽位，或 `is_road_at` 为真 | 道路保持通畅 |
| 该瓦片是水槽位 | 生物群系非水的湖泊依然不放道具 |
| 在建筑占地内 | 墙里不长树 |
| 2 m 间距单元已被占用 | 森林不能变成一堵树冠之墙 |

存活者获得 `[0, TAU)` 内的随机偏航角和 `[0.85, 1.2]` 内的均匀缩放。

## 碰撞与遮挡体输出

一个区块携带两个 `(Aabb, u64)` 列表：`Chunk::colliders`（裁剪到本区块的建筑体，
加上每个道具的实心盒）与 `Chunk::occluder_boxes()`（同样的建筑体，加上
`PropKind::is_occluder()` 为真的道具 —— 只有树）。

合并的粒度是**每段建筑行程一个盒，而不是每个体素一个盒**，这是这里最需要理解的
一点。`merge_voxel_runs` 贪心地折叠预制件的体素：每个 `(x, z)` 列先变成一个竖直
行程，行程按高度跨度分组，然后在邻居一致时沿 `+X` 和 `+Z` 生长。一座实心房子变成
一个盒，L 形的变成两三个，而程序化回退恰好是两个（墙体行程加屋顶体）。

为什么重要：`noxel-visibility` **每一帧**都对这些体做射线测试，而淡出是按物体
进行的（让半个屋顶淡出毫无意义）。一座 400 栋建筑的城镇就是 400 个盒，一条射线
只需几微秒；每个体素一个盒会是数万个，会让淡出变得无法承受。道具同理：一棵树是
一个细实心树干（半宽 0.28 m，高 1.8 m）加一个宽树冠遮挡体（半宽 1.5 m，基高
1.5 m，高 3.6 m）。

id 在重新生成后保持稳定 —— `BuildingInstance::id` 哈希预制件名、原点与偏航角；
`PropInstance::id` 哈希名称与量化到 1/16 m 的位置 —— 所以碰撞体 id 能在逐出与
重新生成后存活。

## 区块数据布局

`Chunk` 是稠密且扁平的：每个数组长度都是 `tiles * tiles`，按 `y * tiles + x`
行主序 —— 这正是渲染器上传的顺序，也是 `chunk_to_string` 打印的顺序。

| 字段 | 类型 | 内容 |
|---|---|---|
| `pos` | `ChunkPos` | 它所在的位置；`y` 是 **Z** 轴 |
| `tiles` | `Vec<u32>` | 瓦片 id |
| `heights` | `Vec<f32>` | 每瓦片的地形高度，米 |
| `slopes` | `Vec<f32>` | 每瓦片的坡度大小 |
| `biome` | `BiomeId` | 区块中心处的生物群系 |
| `colliders` | `Vec<(Aabb, u64)>` | 静态碰撞，如上所述 |
| `props` | `Vec<PropInstance>` | 树、岩石，以及放置的其他任何东西 |
| `buildings` | `Vec<BuildingInstance>` | 与本区块相交的建筑 |
| `roads` | `Vec<RoadSegment>` | 裁剪到本区块的道路中心线 |
| `has_town` | `bool` | 这里是否有城镇的任何一部分 |
| `generated_ms` | `f32` | 生成耗时，从缓存读取时为 `0` |
| `tile_size` | `f32` | 每瓦片的米数，从配置复制而来 |

访问器绝不 panic：`tile`/`height`/`slope` 越界时返回 `0`，`index` 返回 `None`。
`is_walkable` 把越界当作不可行走；`blocks_sight` 把它当作阻挡 —— 角色不能走出
已加载世界的边缘，可见性也不能看穿它。

## 流式加载

`WorldStreamer` 拥有一个 `WorldGenerator` 和一个区块 LRU 缓存。

| 旋钮 | 默认值 | 效果 |
|---|---|---|
| `view_distance_chunks` | 6 | 焦点周围生成的区块：`(2v+1)² = 169` |
| `keep_distance_chunks` | 8 | 更远的（切比雪夫距离）会被逐出 |
| `max_cached_chunks` | 256 | 硬上限；最远、最久未被触碰的先逐出 |

`update(focus)` 在什么都没变时开销很低：如果焦点仍在同一个区块且视距未变，它立即
返回，并报告 `generated_this_update == 0`。生命周期计数器（`cache_hits`、
`cache_misses`）与每次更新的计数器（`generated_this_update`、
`evicted_this_update`）是分开的。移动一个区块会生成一行或一列新区块（13 个），
并且在越过保留环之前不会逐出任何东西。

## 查询

`WorldGenerator` 在任何坐标上都能从构建区块所用的同一批字段作答，而不生成任何
东西；`WorldStreamer` 优先使用驻留区块，回退到生成器。

| 查询 | Generator | Streamer | 备注 |
|---|---|---|---|
| `sample_height(x, z)` | ✔ | `height_at(Vec3)` | 在已加载区块内精确 |
| `sample_slope(x, z)` | ✔ | — | 高差除以水平距离 |
| `biome_at(x, z)` | ✔ | — | |
| `is_road_at(x, z)` | ✔ | — | 格网加上城镇街道 |
| `town_at(ChunkPos)` | ✔ | — | `Option<TownPlan>` |
| `tile_at(Vec3)` | — | ✔ | 未加载时为 `None` |
| `is_walkable(Vec3)` | — | ✔ | 回退到高度与坡度 |
| `blocks_sight(Vec3)` | — | ✔ | 在外部报告 `true` |
| `colliders_in` / `occluders_in` / `props_in` | — | ✔ | 填充调用方的 `Vec` |

非有限输入绝不 panic：`sample_height`/`sample_slope` 返回 `sea_level` 和 `0`，
`biome_at` 返回 `PLAINS`，`is_road_at` 返回 `false`。

## 配置

每个 `WorldConfig` 字段，以及 `WorldConfig::new(seed)` 使用的值（`default()` 相同，
只是种子为 `0`）：

| 字段 | 默认值 | 备注 |
|---|---|---|
| `seed` | `0` | 生成的一切都由它派生 |
| `tile_size` | `1.0` | 每瓦片的米数 |
| `tiles_per_chunk` | `32` | 钳制到 `1..=MAX_TILES_PER_CHUNK`（1024） |
| `chunk_world_size` | `32.0` | 米；改动上面两项后要调用 `sync_sizes()` |
| `view_distance_chunks` | `6` | |
| `keep_distance_chunks` | `8` | `view + 2`，永不低于 `view` |
| `max_cached_chunks` | `256` | 至少为 1 |
| `sea_level` | `0.0` | 水位线 |
| `height_scale` | `8.0` | 起伏的米数 |
| `road_grid_chunks` | `8` | 256 m 格网 |
| `road_jitter` | `0.25` | 一条线可以游走的比例，以区块为单位 |
| `road_width_tiles` | `3` | 铺装宽度 |
| `town_spacing_chunks` | `10` | 每第 10 个格点位置一个城镇 |
| `town_radius_chunks` | `3` | 建成区半径 |
| `buildings_per_town` | `18` | 风格缩放之前；`0` 会预留地块 |
| `generate_props` | `true` | 总开关 |
| `prop_density` | `0.02` | 由生物群系自身的密度缩放 |

配置是被消毒而非被信任的：`chunk_world_size()` 和 `tile_size()` 会从零值或非有限
字段推导出回退值，`safe_tiles_per_chunk()` 做钳制，`road_spacing()` 和
`town_spacing()` 绝不返回零，`sync_sizes()` 会重新推导区块尺寸。

## 确定性保证

- `two_generation_orders_agree`：生成一个区块，访问四个无关区块，再重新生成目标
  区块 —— 文本转储相等。碰撞体 id 与包围盒也能在重新生成后存活
  （`colliders_have_stable_ids_and_finite_bounds`）。
- `chunk_to_string` 逐字节稳定，这使它成为一种黄金世界格式；高度以分米打印，因此
  diff 显示的是米级变化，而不是浮点噪声。
- 高度场是连续的：0.1 m 的步长让地表移动不到 0.5 m，而把步长减半大致也让最大
  变化减半。

唯一破坏确定性的事，是在区块被缓存之后修改配置：`config_mut()` 立即生效，但已有
的 streamer 必须被 `clear()`。

## 编写预制件

预制件是一个小型体素模型（`noxel_asset::format::Prefab`）。把它写成 JSON 并在
资源清单中列出：

```json
{
  "name": "house_small",
  "size": [5, 3, 4],
  "tags": ["building", "residential"],
  "voxels": [{ "x": 0, "y": 0, "z": 0, "tile": 12 }],
  "spawns": [{ "name": "door", "position": [2.0, 0.0, 3.5], "yaw": 0.0 }],
  "occluders": [[0, 0, 0, 4, 2, 3]]
}
```

| 键 | 必填 | 含义 |
|---|---|---|
| `name` | 是 | 供 `BuildingInstance::prefab` 和 `AssetDb::prefab(path)` 使用 |
| `size` | 是 | 以瓦片计的 `[x, y, z]`；`size[1] == 0` 使它不能用作建筑 |
| `tags` | 否 | `"building"`/`"house"` 使它在城镇地块中优先 |
| `voxels` | 否 | 被填充的单元；缺席的单元是空的空间 |
| `props` | 否 | `kind`、`position`，可选的 `yaw`/`scale` |
| `spawns` | 否 | 具名标记，例如一扇门 |
| `occluders` | 否 | `[x0,y0,z0,x1,y1,z1]` 体素包围盒，用来遮挡玩家 |

决定你的预制件是否被采用的规则：地块在旋转到其朝向后提供 `plot_size - 1` 个瓦片
（东/西会交换 X 与 Z），因此 `5x4` 的预制件需要 `6x5` 的地块；`choose_footprint`
忽略任一轴超过 12 格的预制件；`size[1]` 会变成 `size[1] * tile_size` 米高。
`occluders` 为空时，生成器会合并 `voxels` —— 当贪心合并会盖住庭院时，请显式编写
它们，因为覆盖空旷空间的盒子会让本来可见的东西淡出并被遮挡。体素 `(0, 0, 0)` 是
最小角，而建筑会向地块内缩进半格，使预留的边距保持为可见的缝隙。

体素 `tile` 值是地形所用同一个 `TileSet` 中的 id。渲染器不直接绘制预制件体素
—— 它们为包围盒、碰撞和遮挡提供数据 —— 所以没有瓦片的体素依然会碰撞。

## 常见错误

- **「我改了种子，世界却没变。」** streamer 的缓存仍持有旧区块。改动 `seed`、
  `tile_size` 或 `tiles_per_chunk` 之后要调用 `WorldStreamer::clear()`。
- **「`Chunk::tiles()` 返回 0。」** 你手工把 `chunk.tiles` 换成了非平方的长度；
  现在每个访问器都退化到它的越界值。
- **「每个瓦片都是 id 0。」** 瓦片集是空的，或缺少生成器索要的每个名称。检查
  `generator.tile_set().tile_by_name("grass")`：如果清单没有加载，`App` 会回退到
  一个空 `TileSet`。
- **「森林里缺道具。」** `generate_props` 关着、`prop_density` 为 0，或者该瓦片
  是道路或水的瓦片。
- **「`town_at` 对荒野返回了规划。」** 城镇半径是 3 个区块，所以每个方向最多七个
  区块都会报告 `has_town`。用 `TownPlan::contains_world` 测试位置，而不是测试
  区块。
- **「在城镇里相机淡出很贵。」** 你正在把未合并的体加进可见性场景；生成器自己的
  遮挡体正是为此而合并的。
- **「`sample_height` 与某个区块瓦片不一致。」** 区块高度是在瓦片*中心*采样的：
  `origin + (tile + 0.5) * tile_size`，不是瓦片角点。

# 摄像机与可见性

`noxel-camera` 构建视图；`noxel-visibility` 决定视图里什么值得绘制。本指南涵盖这两者，外加一套用于排查物体丢失的调试流程。

## `TopDownCamera`

相机装置持有*意图* —— 玩家在哪里、相机滞后多少、抖动多强 —— 并按需产出一个 `CameraView`。它从不接触场景，所以过场动画、室内和玩法相机是同一个类型的不同配置。

```rust
use noxel_camera::TopDownCamera;
use noxel_core::math::Vec3;

let mut camera = TopDownCamera::pixel_art(320, 180); // straight down, pixel snapping
camera.set_ortho_height(20.0);                       // 20 m of world on screen
camera.set_smoothing(0.05);                          // 5% of the gap left per second
camera.set_deadzone(1.6, 1.2, 0.0);                  // world units
camera.set_look_ahead(0.22, 2.5);                    // seconds of motion, capped in metres
camera.set_clip_planes(1.0, 300.0);

// Once per frame, after the player has moved:
camera.follow_with_velocity(Vec3::ZERO, Vec3::new(1.0, 0.0, 0.0), 1.0 / 60.0);
let view = camera.view(320.0 / 180.0);
```

| 构造函数 | 结果 |
|---|---|
| `new(ProjectionMode)` | 焦点在原点，俯仰垂直向下，距离 40 m，平滑 0.05，没有死区也没有前瞻，近平面 0.1，远平面 400 |
| `pixel_art(w, h)` | 正交投影 `height: 20.0`，外加 `PixelPerfect::at(w, h)` |
| `perspective_tilted(fov_y, pitch)` | 按给定俯仰角配置的透视相机装置 |

### 跟随、死区、平滑

`follow_with_velocity(target, velocity, dt)` 依次做四件事：

1. **前瞻** —— `velocity * look_ahead`，以 `max_look_ahead` 米为上限。一点点提前量（0.1–0.3 s）能让奔跑中的角色保持在画面中央，而不是被拖在死区边缘。
2. **死区** —— 在目标离开一个 `deadzone.x` × `deadzone.y` 的盒子（垂直方向再加上 `deadzone_y`）之前，焦点原地不动，之后也只移动到那个盒子的边缘。没有死区时，移动的目标看起来像是在用橡皮筋拖着相机走。
3. **平滑** —— `focus += (desired - focus) * damp_factor(smoothing, dt)`。
4. **旋转**（启用时）—— 走较短的一侧，每次都只转过*剩余*角度的一部分。

`damp_factor(smoothing, dt)` 就是 `1 - smoothing^dt`，这让平滑与帧率无关：两个半秒的步长与一个一秒的步长留下相同的残差。两个边界情形是刻意设计的 —— `dt <= 0` 返回 0（没有时间流逝，就不允许任何移动），`smoothing <= 0` 返回 1（吸附）。曾经真有一个 `damp_factor(0)` 返回「永不移动」的 bug，被测试抓了出来；如果你要自己写平滑，请用这个函数，而不是 `1 - powf(..)`。

```rust
use noxel_core::math::damp_factor;

let one = 1.0 - damp_factor(0.1, 1.0);
let two = (1.0 - damp_factor(0.1, 0.5)).powi(2);
assert!((one - two).abs() < 1e-5);
```

### 偏航、俯仰、距离、缩放、边界

- `set_yaw(yaw)` 设置一个目标值并启用旋转；`lock_rotation()` 把它冻结；`set_yaw_immediate(yaw)` 不做平滑直接写入（区域用的就是它，因为区域的交叉淡入本身就跨越多帧，再加一级平滑会让相机到达的时间与缩放对不上）。
- `set_pitch(p)` 会钳制到 `[0.15, PI/2]`。垂直向下是像素画的默认值；低于约 9° 时俯视地图就没法看了，所以这里做了钳制。
- `set_distance(d)` 钳制到 `[1, 1000]`；`zoom_by(factor)` 乘以正交高度并钳制到 `[2, 200]` —— 缩放滚轮必须是乘性的，否则两端的手感都不对。
- `set_eye_offset(h)` 抬高视点，但不改变注视方向。
- `set_bounds(Some(aabb))` 让可见矩形留在一个区域内：逐轴来看，区域比视野大时做钳制，区域更小时则把视野居中。

### `PixelPerfect` 与 `view`

`view(aspect)` 是唯一会改动吸附状态的方法，所以每帧只调用一次，并把结果同时交给可见性系统和渲染器 —— 两者必须一致。

- 非有限的焦点会被恢复到原点，而不是传进视图投影矩阵（那会让整帧变成空白）。
- `snap_focus` 把焦点量化到整数个内部像素：`units_per_pixel = ortho_height / internal_height`。仅对正交投影有效。
- 抖动偏移是在吸附*之前*采样的，所以抖动不会和像素网格打架。
- 接近垂直向下时（`pitch > PI/2 - 0.02`），世界上方向与视线方向平行，`look_at_rh` 无法据此构建基底；装置改用由偏航角推出的朝向，于是转动相机是让地图跟着转，而不是让侧倾突然跳变。
- `world_units_per_pixel()`、`snapped_focus()`、`eye_position()` 和 `visible_ground_rect(aspect)`（倾斜时沿视线轴按 `min(1/sin(pitch), 4)` 加宽）是引擎其余部分读取的接口。

`PixelPerfect::at(320, 180)` 启用 `snap_focus` 与 `snap_sprites`；`PixelPerfect::OFF` 把两者都关掉。`snap_to_pixels(world_size, units_per_pixel)` 对一个*尺寸*取整，同时保持位置连续 —— 这能修掉精灵在移动时于 15 px 和 16 px 之间来回跳的问题。

### 抖动

基于创伤值：`add_trauma(amount)` 在 1 处饱和，创伤值线性衰减，偏移量是 `trauma²` 再按各轴的哈希噪声缩放。平方让抖动起得干脆、落得柔和；线性衰减会让人觉得相机是被推着走的。

| 设置项 | `new()` | `explosive()` | `rumble()` |
|---|---|---|---|
| `max_offset` | 0.55 m | 1.1 m | 0.18 m |
| `max_roll` | 0.035 rad | 0.09 rad | 0.008 rad |
| `frequency` | 18 Hz | 24 Hz | 9 Hz |
| `decay` | 1.25 /s | 1.6 /s | 0.9 /s |

噪声是 `shake_noise(step, axis, seed)`，以步进计数器为索引，而不是以墙上时钟为索引，所以录制下来的创伤事件会重放出完全相同的运动。`noise1d` 用 smoothstep 在相邻哈希之间插值，因此抖动读起来是低沉的隆隆声，而不是逐帧的雪花噪点。`roll()` 与 `offset()` 是分开的：一点点侧倾，正是有说服力的抖动与不稳的平移之间的区别。

### 区域

`CameraZone` 是一个轴对齐区域，加上它所覆盖的设置：`projection`、`yaw`、`pitch`、`smoothing`、`zoom`、`camera_bounds`、`fixed_focus`。`ZoneKind`（`Follow`、`Fixed`、`LockedYaw`、`Interior`、`Cutscene`）给它贴上标签，供叠加显示和脚本使用。

```rust
use noxel_camera::TopDownCamera;
use noxel_camera::zone::{CameraZone, ZoneBlend, apply_zone};
use noxel_core::math::{Aabb, Vec3};

let mut camera = TopDownCamera::pixel_art(320, 180);
let house = CameraZone::interior(
    "house",
    Aabb::new(Vec3::new(10.0, -5.0, 10.0), Vec3::new(30.0, 20.0, 30.0)),
    0.0,
);
let mut blend = ZoneBlend::new();
blend.update(std::slice::from_ref(&house), Vec3::new(20.0, 1.0, 20.0), 1.0 / 60.0);
if blend.amount() > 0.0 {
    apply_zone(&mut camera, &house, blend.amount());
}
```

`select_zone(zones, point)` 会选出包含该点的最高优先级区域，遇到平手时取*更小*的区域 —— 当一个「门口」区域位于「城镇」区域内部时，这正是你要的行为。`ZoneBlend` 朝「处于区域内」平滑过渡，两端各带 0.1% 的吸附，这样相机不会去追一个没人看得出来的差值。混合是刻意为之：在室外与室内的缩放之间硬切，是俯视相机能做出来的最刺眼的事情。

## 三级剔除器

`VisibilitySystem::update(&VisibilityInput, &RenderSettings) -> VisibleSet` 分三个阶段精筛候选集合，每个阶段都只能*移除*。

**阶段 1，逐实例，按场景顺序：**

| 顺序 | 测试 | `CullReason` |
|---|---|---|
| 1 | `!instance.visible` | `Hidden` |
| 2 | `visible_layers & instance.layer == 0` | `LayerDisabled` |
| 3 | `instance.bounds().is_empty()` | `TooSmall`（计入，但不产生 `culled` 条目） |
| 4 | 位于近平面之后 | `NearPlane` |
| 5 | 在视锥之外（经过 `frustum_margin` 之后） | `Frustum` |
| 6 | 超过该层的距离上限 | `Distance` |
| 7 | 屏幕半径小于 `min_screen_radius` | `TooSmall` |
| 8 | 其他情况 | 绘制，并带上它的 LOD |

`flags.always_visible` 跳过所有测试。

**阶段 2 —— 遮挡：** 当 `cull_occluded` 打开时，每个幸存者都会用 `OcclusionIndex::is_occluded` 测试；被挡住的记为 `Occluded`。`always_visible` 除外。

**阶段 3 —— 淡出：** 相机与焦点之间的遮挡物淡出，每个被绘制项的 `alpha` 由淡出表填入。这个阶段不移除任何东西。

`CullCounts` 累计 `considered`、`drawn`、`frustum`、`near_plane`、`distance`、`too_small`、`occluded`、`layer_disabled`、`hidden` 和 `faded`，并提供 `rejected()`、`draw_ratio()` 与 `summary()`。`CullReason::label()` 给出叠加层用的短文本：`drawn`、`frustum`、`near`、`far`、`small`、`occluded`、`layer`、`hidden`。

| `CullSettings` | 默认值 | 含义 |
|---|---|---|
| `max_distance` | 250 m | 丢弃离相机更远的任何东西 |
| `layer_distances` | 全 0 | 逐层覆盖；`0` 表示「使用 `max_distance`」（`set_layer_distance(bit, m)`） |
| `min_screen_radius` | 0.45 px | 丢弃屏幕上比这更小的东西 |
| `reference_viewport_height` | 180 | 相机不上报 `world_units_per_pixel` 时使用 |
| `frustum_margin` | 0.0 | 扩大视锥，使物体不会在边缘突然弹出 |

`Culler::units_per_pixel` 在正交投影下是常量，在透视投影下与距离成正比；`screen_radius` 用包围球半径除以它。0.45 px 这个默认值刻意压在像素边界上：亚像素几何的设置成本高于它能带来的贡献。`VisibilityConfig::large_world()` 设定 160 m 的可视距离；`exhaustive()` 为黄金图像测试关掉距离、尺寸和遮挡剔除。

## 遮挡索引

`OcclusionIndex` 针对一棵由**合并后的遮挡物体积**构成的 BVH 回答两个问题 —— 每排建筑或每片树冠一个盒子，绝不是每个体素或三角形一个，因为淡出是按物体进行的（半个屋顶没有意义），而 `noxel-world` 正是为此才输出合并后的结果。它只在 `Scene::revision()` 变化时重建，所以静态世界只需付一次 `O(n log n)` 的代价。

**相机遮挡**投射的是一束射线，而不是一条：一条中心射线，加上位于半边长 `focus_radius`（0.45 m）的正方形四角的四条，瞄准焦点上方 0.4 m 处，再额外加上 `ray_margin`（0.05 m），这样正好落在焦点上的遮挡物不会闪烁。角色是一个盒子，不是一个点 —— 只盖住一侧肩膀的屋顶也必须淡出，而单条中心射线恰好会漏掉玩家最容易注意到的那些情况。`collect_blockers` 返回一个排好序、去过重的句柄集合。

**遮挡剔除**从相机射向物体中心，并提前 `bounding_sphere_radius * 0.5` 停下，这样贴着墙的物体不会穿过共享边界把自己遮挡掉。只有屏幕半径至多 `cull_max_screen_radius`（24 px）的物体才会被考虑 —— 剔除一个大物体省不下多少，却会明显地跳变 —— 并且物体自身的句柄被排除在外。`OcclusionSettings::fade_only()` 是游戏还在开发阶段时的安全配置：淡出照常工作，但什么都不会消失。

| `FadeSettings` | 默认值 | 含义 |
|---|---|---|
| `min_alpha` | 0.25 | 遮挡物会变得多透明 —— **不是** 0 |
| `speed` | 0.02 | 一秒之后仍保留的剩余 alpha 距离比例 |
| `enabled` | true | 总开关 |

淡出是平滑的而不是瞬间跳变的，因为一个不再遮挡的屋顶不能在一帧之内变回不透明；而一个*仍在淡出*的物体，即使射线已经不再打到它，也会继续淡出 —— 否则在玩家从它下面走出来的那一刻就会跳变。`min_alpha: 0.25` 保留一层淡淡的轮廓，仍然读得出是屋顶；在俯视游戏里，几何体被完全隐藏会让人失去方向感。`FadeTable` 为那些用自己的逻辑驱动淡出的游戏暴露同样的平滑处理，`VisibilitySystem::fade_of(handle)` / `fading_count()` 用来读取它。

## 按屏幕半径分级的 LOD

阈值用的是**包围半径的屏幕空间像素数**，而不是距离，因为决定一次切换是否看得见的就是它：远处的大物体和近处的小物体可能需要同样的处理。

| `LodLevels` | 默认值 | 含义 |
|---|---|---|
| `full` | 12.0 px | `>= full` 为 LOD 0 |
| `medium` | 5.0 px | `>= medium` 为 LOD 1 |
| `low` | 1.5 px | `>= low` 为 LOD 2；再小就是 LOD 3 |
| `viewport_height` | 180 | 世界坐标到像素的换算 |
| `distance_bias` | 0.0 | 每级额外增加的距离；0 表示关闭偏置 |

渲染器对每个实例只绘制一个网格，所以 LOD 并不切换网格；它告诉引擎其余部分某个实例值多少开销（NPC 系统把远处的代理降到更便宜的分层；流式加载据此决定保留什么；游戏可以在 `lod >= 2` 时切换网格）。`LodSelection::update_fraction_for` 对级别 0–3 分别给出 1.0、0.5、0.25 和 0.1，而 `should_update(instance_id, frame)` 在 `(frame + instance_id) % period == 0` 时返回 true —— 降低更新频率，却不需要逐代理记账，也不会闪烁。

## 把它们都画出来

所有调试绘制默认都是关闭的，因为每个线框都要花一次查询：

```rust
use noxel_debug::{DebugConfig, DebugSystem};

let mut debug = DebugSystem::new(DebugConfig::verbose()); // camera panel + wireframes
// Per frame, after the visibility pass:
// debug.draw(&mut framebuffer, Some(&view));
// debug.draw_occlusion(&mut framebuffer, &view, focus, &blocker_bounds);
// debug.draw_boxes(&mut framebuffer, &view, &collider_bounds);
// debug.draw_marker(&mut framebuffer, &view, player_position, 0.6, Color8::RED);
```

| 调用 | 显示内容 |
|---|---|
| `draw` | 统计面板、帧时间曲线图、剔除计数器，以及可选的相机线 |
| `draw_occlusion` | 一条黄色的相机到焦点连线，以及每个遮挡体积一个洋红色盒子 |
| `draw_boxes` | 青色盒子，用于碰撞可视化 |
| `draw_marker` | 世界坐标处的一个十字标记 |

`VisibilitySystem::summary()` 是一行式的读数（`visible N | drawn/considered (...) | occluders N | fading N`）。想看清装置本身而不是剔除结果时，就把所有 `instance.flags.occluder` 为真、且 `fade_of(handle)` 小于 1 的实例框出来 —— 那会显示屋顶*为什么*是半透明的。

## 我的物体为什么看不见？

1. **它在场景里吗？** `Scene::instance(handle)` 返回 `None`，说明这个句柄已被移除或从未创建；`instance_count()` 和 `summary()` 会告诉你场景里有什么。
2. **`instance.visible` 呢？** 为 `false` 即 `Hidden`，光线追踪器也会跳过它。
3. **层呢？** `visible_layers & instance.layer == 0` 即 `LayerDisabled` —— 室内隐藏屋顶层靠的就是这个。检查 `VisibilityInput::with_layers`。
4. **空网格？** 空网格会被跳过并给出空边界，剔除器把它计入 `TooSmall`，*而不*产生 `culled` 条目：不在 `culled` 里并不代表这个物体通过了。
5. **边界过期了？** `Instance::bounds` 是私有的，由 `Scene::update_bounds`/`update_all_bounds` 刷新。如果你直接写了 `instance.transform`，剔除器测的还是旧盒子 —— 通常就是位于原点的那一个。
6. **在近平面之后？** 即 `NearPlane`：`camera.depth_of(centre)` 比 `-radius - near` 还要负。
7. **在视锥之外？** 把 `frustum_margin = 1.0` 设上，就能区分「在边缘弹出」和「一直不出现」。
8. **太远？** 即 `Distance`。`distance_for_layer` 用 `layer.trailing_zeros()` 作为索引，所以一个*组合*了多个位的值会悄悄采用最低位的覆盖值。一个实例，一个层位。
9. **太小？** 即 `TooSmall`：`bounding_sphere_radius / units_per_pixel < 0.45`。在 320x180 下，0.2 m 的物体在约 5 m 之外就不到一个像素了。
10. **是遮挡剔除？** 即 `Occluded` —— 用 `cull_occluded: false` 确认，然后检查你的遮挡体积是否已经合并、有没有盖住空白空间。
11. **是淡出了，而不是消失？** 被挡住的遮挡物会降到 `min_alpha` 0.25，并且仍在绘制；检查 `CullCounts::faded` 和 `fade_of`。
12. **材质？** `Cutout` 在阈值以下丢弃，`Blend`/`Additive` 在第二遍绘制且不写深度，而 `base_color` 为黑色的无光照材质就是黑的。Alpha <= 0.001 会被直接跳过。
13. **画了，但被什么挡住了？** `Framebuffer::id_at(x, y)` 会指出某个像素属于哪个实例，这能把「被剔除」和「被几何体挡住」区分开。

## 常见错误

- **「玩家移动时相机抖动。」** `PixelPerfect::at(w, h)` 必须使用与帧缓冲相同的内部分辨率，否则吸附会落在像素之间。
- **「帧率越高，相机越滞后。」** 你用了手写的 `1 - powf(smoothing, dt)` 或乘以 `dt` 来做平滑。请用 `damp_factor`。
- **「`set_smoothing(0)` 没有吸附。」** `dt <= 0` 时 `damp_factor` 返回 0，所以零长度的帧无法让相机瞬移。
- **「进入建筑时相机猛地一跳。」** 你给 `apply_zone` 传的是 `t = 1.0`，而不是 `ZoneBlend::amount()`。
- **「转动相机时地图跟着侧倾。」** 你在垂直向下的俯仰角上传了 `up = Vec3::Y`；请使用装置（或它由偏航角推出的朝向）。
- **「整个层都消失了。」** `distance_for_layer` 以该层最低的置位为索引；一个实例应当只携带一个层位。
- **「遮挡索引每帧都在重建。」** 有东西每帧调用 `Scene::touch()`，或者通过 `*_mut` 访问器做修改。任何修改都会推进 `Scene::revision()`，使 BVH 和淡出记账失效；把静态几何体移出每帧路径。

# 快速上手

从空目录到跑起来的村庄，大约十分钟。

---

## 0. 前置条件

Rust 1.85 或更高版本（本工作区使用 edition 2024）：

```bash
rustup update stable
rustc --version     # 1.85+
```

没有别的了。不需要显卡驱动，不需要系统库，没有子模块——引擎零第三方依赖（`adr/0002-no-dependencies.md`）。

> **如果找不到 `cargo`**，说明这台机器把工具链放在默认 `PATH` 之外。先执行 `export PATH="$HOME/.cargo/bin:$PATH"`，或者把它加进你的 shell 配置。

---

## 0b. 或者直接运行预构建的示例

如果你没有 Rust，或者只是想看看引擎跑起来是什么样，就在一台有 Rust 的机器上构建这个可迁移的示例包：

```bash
./scripts/build-dist.sh
```

它会产出 `dist/`：

```
dist/
  town-demo      the compiled example
  noxel-gen      the asset generator
  assets/        every texture, tileset, prefab and sprite it needs
  README.txt
```

`dist/` 不需要工具链、不需要源码树、也不需要网络。把它复制到任何地方——U 盘、同事的笔记本——然后运行 `./town-demo`。可执行文件会在自己旁边找到资源，所以工作目录无关紧要。

```bash
cd dist && ./town-demo --frames 300
```

本指南剩下的部分都是关于在源码上工作的。

## 0c. 或者直接在窗口里玩

引擎自带一个窗口宿主。打开 `window` feature 即可：

```bash
cargo run -p town-demo --features window -- --window
# 或者等价地：./scripts/run-window.sh
```

| 按键 | 作用 |
|---|---|
| `W A S D` 或方向键 | 行走 |
| `shift` | 奔跑 |
| `F1` | 切换统计叠加层 |
| `F8` | 把当前帧写成 PNG |
| `escape` | 退出 |

demo 会沿脚本路线自动行走，直到你碰一下操作键；从那一刻起它就归你了，而且不会把控制权收回去。这里没有模式开关——输入就是赢，所以同一个二进制既是 CI 的帧生成器，也是一款游戏。

`window` feature 是唯一会引入 `winit` 与 `softbuffer` 的地方，默认关闭，因此普通的 `cargo build` 依然什么都不下载（[ADR 0011](adr/0011-窗口.md)）。

## 1. 构建与测试

```bash
cd noxel
cargo build --workspace
cargo test  --workspace
```

整个测试套件有几百个测试，几秒钟就能跑完，且不需要显示服务器。如果在全新检出的代码上测试失败，那是一个真实的发现——改动任何东西之前先读 `adr/0010-testing-strategy.md`。

---

## 2. 生成资源

```bash
cargo run -p noxel-gen -- generate
```

这会把每一张纹理、图集、tileset、预制体、sprite sheet 和清单写入 `examples/town-demo/assets/`。生成器是确定性的：跑两次不会改变任何字节，因此 pull 之后重新跑一遍等于什么都没做。

```bash
cargo run -p noxel-gen -- verify      # exits non-zero if a file was tampered with
cargo run -p noxel-gen -- list        # what it can produce
cargo run -p noxel-gen -- preview --out frames/atlas   # a contact sheet of every image
```

运行引擎**并不**需要先生成资源。资源树缺失时会回退到程序化内容和一张占位纹理，正因如此，测试套件能在一毫秒内构建出一个可用的 `App`。

---

## 3. 运行演示

```bash
cargo run -p town-demo -- --frames 300 --dump frames
```

然后打开 `frames/frame_000299.png`。你应该会看到一个村庄：广场、街道、几十栋建筑、树木，以及一个沿脚本路线行走的角色，相机跟在后面。角落里的 HUD 会显示种子和帧号。

一些有用的变体：

```bash
# Ray-traced shadows and ambient occlusion on the same world.
cargo run -p town-demo -- --mode hybrid --frames 60

# A bigger crowd.
cargo run -p town-demo -- --npcs 600 --frames 300

# One frame, every statistic, no files written.
cargo run -p town-demo -- --stats

# What does this seed actually generate?
cargo run -p town-demo -- --seed 12345 --world-info

# A different world.
cargo run -p town-demo -- --seed 0xC0FFEE --frames 300
```

`--help` 会列出全部选项。

## 4. 你的第一个 app

基于 Noxel 的引擎就是一个 `App` 加上若干插件。下面这段代码完整可运行：

```rust,no_run
use noxel_app::{App, AppConfig, Plugin};
use noxel_core::math::{Color, Transform, Vec3};
use noxel_render::material::Material;
use noxel_render::mesh::Mesh;

/// Spawns a cube and spins it.
struct Spinner {
    instance: Option<noxel_render::scene::InstanceHandle>,
    angle: f32,
}

impl Plugin for Spinner {
    fn name(&self) -> &str { "spinner" }

    fn build(&mut self, app: &mut App) {
        let mesh = app.scene_mut().add_mesh(Mesh::cube(2.0));
        let material = app.scene_mut().add_material(Material::lit("cube", Color::WHITE));
        self.instance = Some(
            app.scene_mut().spawn("cube", mesh, material, Transform::IDENTITY),
        );
    }

    fn update(&mut self, app: &mut App, dt: f32) {
        self.angle += dt;
        if let Some(instance) = self.instance {
            app.scene_mut().set_transform(
                instance,
                Transform::from_translation(Vec3::new(0.0, 1.0, 0.0)).with_yaw(self.angle),
            );
        }
    }
}

fn main() {
    let mut app = App::new(AppConfig::default()).unwrap();
    app.add_plugin(Spinner { instance: None, angle: 0.0 });
    for _ in 0..120 {
        app.step(1.0 / 60.0);
    }
    // `app.resolve()` is now an sRGB image; write it, or blit it to a window.
    let image = app.resolve();
    println!("{}x{}", image.width, image.height);
}
```

有三点值得注意：

- `App::step(dt)` 运行完整的一帧：固定更新、相机、流式加载、剔除、渲染、叠加层。
- `Scene` 发出的是句柄而不是索引。失效的句柄会被跳过，而不会悄悄指向错误的对象，正因如此，流式内容的卸载顺序无关紧要。
- `resolve()` 是线性 HDR 变成 sRGB 字节的地方。在它之前，没有任何颜色是可以拿给别人看的。

## 5. 看清正在发生什么

Noxel 没有 UI（`adr/0009-no-ui.md`），但它有一套调试系统：

```rust,no_run
# use noxel_app::{App, AppConfig};
# let mut app = App::new(AppConfig::default()).unwrap();
app.debug_mut().record_counter("npcs", 240.0);
app.debug_mut().record_section("physics", 2.4);
app.step(1.0 / 60.0);
println!("{}", app.debug().report());
```

报告里有每个区段的滚动均值、p50 和 p95，还有一条预算线：当某个区段的开销超出配额时会显示 `OVER`。平均帧时间会掩盖卡顿，p95 不会。

想要画面，就导出帧：

```rust,no_run
# use noxel_app::{App, AppConfig};
# let mut app = App::new(AppConfig::default()).unwrap();
let report = app.run_and_capture(60);
// `report.last_image` is a decoded PNG-ready image.
```

再比较两次运行：

```rust,no_run
# use noxel_debug::dump;
# fn example(a: &noxel_asset::image::Image, b: &noxel_asset::image::Image) {
let diff = dump::compare(a, b);
println!("{}", diff.summary());
assert!(diff.within(0.0, 0), "the frame changed");
# }
```

之所以能做到零容差，是因为渲染是确定性的（`adr/0008-deterministic-rendering.md`）。

## 6. 添加窗口

引擎从不打开窗口。`App` 产出一个 `Framebuffer`；如何呈现它是宿主的事，这让 `noxel-app` 里没有平台相关代码。

```text
your host loop
  ├─ fill app.input_mut() from the platform's events
  ├─ app.step(real_dt)
  ├─ let image = app.resolve();          // sRGB bytes, width*height*4
  └─ upload `image.pixels` to your texture and swap buffers
```

`guides/windowing.md` 里有一个完整的 `winit` 示例，而 `examples/town-demo` 就是同一个 app，只是把窗口换成了 PNG 写出器。

## 常见错误

**「全黑。」**
帧缓冲是线性的，初值为零。要么加一个光源（`scene.add_light(Light::sun())`），要么提高环境光项，要么设置 `scene.background`。基色为黑的无光照材质同样是黑的，这一点很容易不小心踩到。

**「我的物体不见了。」**
照着 `05-camera-and-visibility.md` 的检查清单排查。常见原因按顺序如下：它在视锥之外；它超出了 `max_distance`；它的包围球小于 `min_screen_radius`；它的包围盒从未计算过（spawn 之后调用 `Scene::update_all_bounds`）；或者被某个遮挡物吞掉了。

**「颜色不对/发白。」**
你看到的是线性帧缓冲。调用 `resolve()`。

**「什么都不动。」**
对于失效的句柄，`Scene::set_transform` 会返回 `false`。另外检查一下插件的 `update` 是不是你以为的那样：`Plugin::update` 按*固定*步长运行，而不是按帧率。

**「`app.physics_mut().body_mut(h).position = x` 没起作用。」**
直接写字段会在下一次 `step` 时被读取，但刚体缓存的粗检测状态不会。请用 `set_position`。

**「每个种子生成的世界看起来都一样。」**
检查你是否通过 `AppConfig::seed` 传入了种子，*并且* `--seed` 确实到达了 `WorldConfig`。`App::new` 会有意用 `AppConfig::seed` 覆盖 `world.seed`，所以两者只设一个，不要都设。

# ADR 0004 — 一个场景，两个渲染器

**状态：** 已接受
**适用范围：** `noxel-render`

## 背景

需求是同时支持光栅化与光线追踪。诱人的实现方式是两条管线各自持有场景表示，因为二者想要的数据不同：光栅化器想要屏幕空间三角形，光线追踪器想要带 BVH 的世界空间三角形汤。

两份表示意味着两套 bug、两套材质语义，以及一个会随绘制它的渲染器不同而微妙变化的场景。

## 决策

**一个场景、一个相机视图、一个可见集，两份 `Renderer` 实现。**

```rust
pub trait Renderer {
    fn name(&self) -> &'static str;
    fn mode(&self) -> ShadingMode;
    fn resize(&mut self, width: u32, height: u32);
    fn release_cached(&mut self);
    fn render(&mut self, scene: &Scene, camera: &CameraView, visible: Option<&VisibleSet>,
              target: &mut Framebuffer, settings: &RenderSettings) -> RenderStats;
}
```

两者消费同一个 `Scene`（网格、材质、实例、灯光）、同一个 `CameraView`、来自 `noxel-visibility` 的同一个 `VisibleSet`，以及同一个 `RenderSettings`；两者写入同一个 `Framebuffer`（线性 HDR 颜色 + 深度 + 实例 id）。切换渲染器只是 `AppConfig` 上的一个字段。

共有三种模式，它们的区别在于*投射哪些光线*：

| 模式 | 主可见性 | 阴影 | AO | 反射 |
|---|---|---|---|---|
| `Raster` | 光栅化器 | 阴影贴图 | — | — |
| `Hybrid` | 光栅化器 | 光线追踪 | 光线追踪 | — |
| `Raytrace` | 光线追踪器 | 光线追踪 | 光线追踪 | 光线追踪 |

**混合模式是推荐的质量模式。** 光栅化的主通道给出的正是像素艺术所需要的锐利、像素对齐的图像；光线追踪昂贵的部分是*次级*光线，而混合通道投射的恰恰就是这些。这是每个生产级渲染器都会做的取舍。

## 共享语义

两个渲染器读取同一个 `Material`。特别地，设置了 `unlit` 标志的材质在两条路径中都原样返回其基础色，因此用光线追踪器绘制的精灵会解析为**美术作者创作的精确字节**。这一点在 `raster` 与 `raytrace` 中都有测试断言：

```rust
let authored = Color::from_srgb8(87, 143, 201, 255);
// ... render ...
assert_eq!(image.get(8, 8).unwrap().to_hex(), authored.to_srgb8().to_hex());
```

这就是光栅路径默认 `ToneMap::None`，而光线追踪路径使用 `ToneMap::Aces`（`RenderSettings::resolve`）的原因。

## 后果

- 光线追踪器保留自己的加速结构缓存，以 `Scene::revision()` 为键，因此静态场景只需支付一次 BVH 构建。
- 混合模式下的光线追踪器驱动光栅化器完成其主通道，这就是 `RayTracer::raster_mut` 存在的原因。
- 新增渲染器（GPU，或仅统计的无头渲染器）只需实现一个 trait；它之上的所有系统都不变。

## 被否决的替代方案

- **每个渲染器各自持有场景**：必然导致二者漂移。
- **只用光线追踪**：在 960x540 下慢一个数量级，而且会丢掉美术方向所依赖的像素精确性。

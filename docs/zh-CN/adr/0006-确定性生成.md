# ADR 0006 — 世界是 `(seed, address)` 的纯函数

**状态：** 已接受
**适用范围：** `noxel-world`、`noxel-npc`、`noxel-core::rng`

## 背景

一个大型流式世界必须让区块 `(900, -400)` 的生成结果完全一致：无论玩家是从西边走到那里、传送进去，还是读取存档。显而易见的实现——一个被每次生成调用推进的全局 RNG——会让生成依赖顺序，而依赖顺序的生成会破坏：

- **存档**，因为重新加载会重放不同的序列。
- **流式加载**，因为一个被换出又重新生成的区块会与第一版不同，于是玩家走回去时地形会肉眼可见地变化。
- **多线程**，因为区块生成的顺序变得不确定。
- **测试**，因为只有当生成稳定时才能断言一个黄金世界。

## 决策

**每一份生成内容都是世界种子与该内容地址的纯函数。** 生成路径中不存在共享的可变 RNG。

```rust
// One stream per (seed, label, address). Nothing else is consulted.
let mut rng = RngStream::for_chunk(config.seed, "terrain", chunk.x, chunk.z);
```

`RngStream`（`noxel-core::rng`）是一个 PCG32，其种子来自对 `(seed, label, address...)` 的哈希。两个后果自然成立：

- 区块可以**并行**生成，无需加锁，也没有顺序要求。
- 区块可以**脱离邻居**生成——没有任何东西被存进一张要靠邻居填满的排列表。

噪声函数遵循同样的规则。`noxel-core::math::noise` 是**基于哈希而非基于表**的：`value_2d`、`perlin_2d`、`simplex_2d`、`worley_2d`、`fbm_2d`、`ridged_2d` 与 `warped_fbm_2d` 的格点值都派生自整数坐标的哈希，因此任意点都可以孤立采样。

## 后果

- `WorldStreamer::update` 无论已经加载了什么都是确定性的；测试套件以两种不同顺序生成区块并断言结果相同。
- `noxel-npc` 的生成与日程决策、以及人群的层级分配同样如此。
- 生成中的 bug 仅凭种子即可复现，因此可以被报告。
- `RngStream::fork(label)` 为子特性（一座城镇的建筑、一个区块的杂物）派生一条子流，且不可能与父流相关。

## 被否决的替代方案

- **单一全局 RNG，加上生成时派生的每区块种子**：在调用方投机性地生成一个区块（为了预览，或为了跨未加载区域寻路）并消耗掉真正生成所需的随机数之前，它是可行的。
- **基于表的 Perlin 噪声**：需要一张排列表，这没问题，但它让「这个确切点的高度是多少」变成表的函数而非坐标的函数，白白让并行化变复杂。

# ADR 0001 — 坐标系、单位与手性

**状态：** 已接受
**适用范围：** 所有 crate

## 背景

引擎的坐标约定会渗入每一个涉及几何的文件。选错了再想撤销代价高昂，而渲染器、物理与世界生成之间「哪边是上」的分歧，正是镜像关卡与翻转法线的经典来源。

## 决策

| 属性 | 选择 |
|---|---|
| 手性 | **右手坐标系** |
| 上方向 | **`+Y`** |
| 前方向 | **`-Z`**（OpenGL 约定） |
| 旋转 | **弧度**，绕正轴逆时针为正 |
| 矩阵布局 | **列主序**，因此 `Mat4::cols` 能直接匹配 GLSL `mat4` 的上传 |
| 裁剪空间深度 | **`[0, 1]`**（Vulkan/WebGPU/D3D），而非 `[-1, 1]` |
| 世界单位 | **1 米** |
| 图块尺寸 | 默认 1 个世界单位（`WorldConfig::tile_size`） |
| 偏航角 | `0` 朝向 `-Z`；`Vec3::from_yaw(y) == (-sin y, 0, -cos y)` |
| 俯仰角 | 正值表示向*下*看，`PI/2` 为垂直向下 |

## 为什么这样选

**`-Z` 为前方向、`+Y` 为上** 与绝大多数 3D 内容以及开发者读过的每一份教程一致。右手坐标系配 `-Z` 前方向，使相机基为 `(right, up, -forward)`，这正是 `Mat3::from_forward_up` 会计算 `right = forward.cross(hint)` 的原因——一个镜像的基（行列式 `-1`）会悄无声息地翻转三角形绕序，让背面剔除剔掉世界的另一半。

**列主序** 意味着 `Mat4` 无需转置即可交给 GPU 缓冲区。`Mat4::get(row, col)` 的索引方式是 `cols[col][row]`，与字段顺序相反，是本文件中最常见的困惑来源；它用显式的 `match` 实现，以便保持 `const` 可求值。

**深度 `[0, 1]`** 是所有现代 API 的方向。`[-1, 1]` 的投影在能用于 WebGPU 或 Vulkan 之前需要一次重映射，而重映射很容易放错阶段。

**偏航角 0 朝向 `-Z`** 是唯一与 `Vec3::from_yaw` 自洽的约定。因此 `Quat::to_yaw` 提取的是 `wrap_angle((-forward.x).atan2(-forward.z))`，而这个符号在开发期间错了两次——`to_yaw_roundtrips` 测试就是为此存在的。

## 后果

- 俯视相机沿 `-Y` 观察、`up = -Z`（`CameraView::orthographic` 接收一个世界上方向提示），这就是当俯仰角接近 `PI/2` 时 `noxel-camera` 会从偏航角推导屏幕上方向量的原因：在完全垂直向下时，世界上方向与观察方向平行，`look_at_rh` 无法据此构建基。
- 网格从外部看是**逆时针**绕序。`noxel_render::mesh` 中的每个程序化图元都有一个测试断言其三角形朝外。
- 物理使用相同的单位，因此 1 m/s 是合理的步行速度，重力为 `-9.81 m/s^2`。

## 被否决的替代方案

- **`+Z` 为前方向、`-Y` 为上**（某些 CAD 与老引擎使用的「左手系、Z 轴向上」约定）：对大多数美术与开发者都不熟悉，额外的心智转换成本大于收益。
- **`[-1, 1]` 深度**：从标准 OpenGL 投影推导更省事，但对我们打算支持的那些后端来说是错的。
- **图块以像素而非米为单位**：世界空间中的像素单位会让物理参数依赖分辨率，于是改变缩放级别的游戏就得重新调重力。

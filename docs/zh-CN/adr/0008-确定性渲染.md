# ADR 0008 — 确定性渲染与黄金帧

**状态：** 已接受
**适用范围：** `noxel-render`、`noxel-debug`、CI

## 背景

图形代码是引擎中最难测试的部分。渲染回归通常由人盯着截图发现，也就是说发现得晚，而且只有有人去看才会被发现。

CPU 渲染器（ADR 0003）让一个更强的保证成为可能：如果没有任何操作依赖墙上时钟、线程调度或全局随机源，那么同一帧的两次运行产出**相同的字节**。测试于是可以对这些字节做断言。

## 决策

**渲染是确定性的。** 任何渲染器、采样或可见性代码都不得读取时钟、线程 id 或全局 RNG。

具体而言：

- **光线追踪采样**来自 `sampling::Sampler`，它是 `(pixel x, pixel y, frame index, sample index)` 的纯函数。测试 `determinism_two_runs_are_identical` 把同一场景渲染两次，并断言颜色缓冲相等。
- **相机抖动**使用 `CameraShake` 的哈希噪声，以步进计数器而非墙上时间索引，因此重放创伤事件就能精确重放抖动。
- **后处理**在 `temporal_blend == 0` 时没有时间分量。
- **并行光栅化**把帧缓冲切成不相交的行带，且不做浮点重结合，因此并行路径与单线程路径产出相同像素。`parallel_and_sequential_rendering_agree` 断言这一点。
- **可见性**按场景顺序产出其 `VisibleSet`，并且仅在设置了 `track_cull_reasons` 时快照剔除原因。
- **剔除与淡入淡出**在关键处以帧计数而非时间为基础。

`noxel-debug` 把它变成一套工作流：`FrameDumper` 写出 `frame_000123.png`，`dump::compare` 报告差异像素比例、最大通道差与 RMSE，并以 `ImageDiff::within(ratio, delta)` 作为测试所做的断言。`dump::diff_image` 产出一张并排对比图，差异像素染成品红色。

## 黄金测试长什么样

```rust
let report = app.run_and_capture(60);
let reference = png::decode(&std::fs::read("tests/golden/town.png")?)?;
let diff = dump::compare(&report.last_image.unwrap(), &reference);
assert!(diff.within(0.0, 0), "{}", diff.summary());
```

零容忍断言之所以可能，正是因为管线是确定性的。

## 后果

- 增加时间性效果（TAA、运动模糊、依赖帧率的后处理）需要让它显式可选，并记录它所依赖的帧索引。
- 光线追踪器的时间累积由一个显式的帧计数器驱动，`RayTracer::reset_accumulation` 的存在让调用方可以强制一帧干净的结果。
- GPU 后端无法给出这一保证（ADR 0007），这是软件路径保持默认的又一个理由。

## 被否决的替代方案

- **基于容差的模糊图像比较**：每个场景都需要一个容差，会掩盖真正的回归，并让小的系统性误差悄悄累积。
- **比较场景的结构哈希而非像素**：能抓到场景 bug，却抓不到着色 bug，而后者才是真正会坏掉的部分。

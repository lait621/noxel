# ADR 0010 — 测试策略

**状态：** 已接受
**适用范围：** 整个工作区

## 背景

这个引擎主要由 AI agent 并行地、逐个 crate 地编写。这种工作流有一个主要失败模式：能编译、看起来合理、但微妙地错误的代码。agent 看不见屏幕，无法做试玩，也无法培养出「那个阴影不对劲」的直觉。

因此测试在这里不是锦上添花的质量项；它是唯一存在的反馈回路。

## 决策

**每个 crate 都在自己的模块内携带单元测试，每一条非显然的不变量都有一个点名的测试。** 门槛设在这里，是为了让绿色的测试套件成为有意义的证据，而不是装饰。

## 测试是用来做什么的

四个类别，价值递增：

1. **契约测试。** 公共 API 形状与默认值。便宜，能抓到笔误。
2. **不变量测试。** 那些*必须*成立的事：每个程序化网格都朝外绕序；精灵往返回到创作的字节；调色板颜色能走完管线；并行与串行光栅化器一致；生成与顺序无关。
3. **派生数值测试。** 对测试*从几何计算出来*的值做断言，绝不使用从一次失败运行中抄来的数字。`nearest_finds_the_closest` 断言距离落在 `8.5..9.0`，是因为测试能证明最近点在 8.7 之外——而不是因为第一次跑出来就是 8.7。
4. **黄金图像测试。** 用 `noxel-debug::dump::compare` 对照一张已提交的 PNG，之所以可能，是因为渲染是确定性的（ADR 0008）。

## 最重要的一条规则

**当测试失败时，判断错的是哪个：代码还是测试。** 两者都会发生。

- 一个失败并发现真实 bug 的测试正是目的所在。开发期间这套测试抓到过：`Ambient` 半球混合反向、`damp_factor` 在平滑为 `0` 时返回「永不移动」、一个没有深度测试的光栅化器、一个把非 ASCII 码点截断成单字节的字体、一个重复 blit 的泛光通道、共享三角形边被着色两次，以及一个极点三角形退化的 UV 球。
- 一个失败但*期望值*错了的测试同样是真实发现，修法是改测试**并在注释里解释原因**。假装测试是对的、把代码改到通过为止，就是测试套件不再成为证据的方式。

## 约定

- 测试名是句子：`parallel_and_sequential_rendering_agree`，而不是 `test_render_2`。
- 依赖某种顺序的测试断言该顺序，而不是绝对值。
- 除了显式测量墙上时钟的测试之外，没有测试依赖墙上时钟；而那些测试断言的是顺序不变量，绝不是某个时长。
- 每一条与 `unsafe` 相邻的假设都是一个测试：索引算术、位集迭代、世代句柄复用、`swap_remove` 重指向。
- 每一个带有看似随机输入的系统，确定性都有一个显式测试。

## 后果

- 测试套件很大——1518 个测试——几秒内跑完，因为引擎没有依赖，热路径上也没有 I/O。
- 破坏不变量的改动会在到达提交之前被抓到。
- 测试就是文档：`Storage::remove` 关于 `swap_remove` 返回*被移除*元素的注释之所以存在，是因为有个测试抓到了它造成的损坏。

## 被否决的替代方案

- **只做集成测试**：粒度太粗，无法定位失败，也太慢。
- **到处都用快照测试**：没有确定性就很脆弱，而且快照记录 bug 和记录正确结果一样容易。

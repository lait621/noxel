# ADR 0009 — No UI toolkit

**Status:** accepted
**Applies to:** the whole workspace

## Context

Game engines accumulate a UI layer: a main menu, a settings screen, a debug
console, a level editor. Each one is a substantial subsystem — layout, text,
input routing, focus, theming, localisation — and each one has to be maintained
forever.

The original requirement for this project is explicit: **no UI/UX is needed; the
deliverable is documentation instead.** That is an unusual constraint and it
deserves an architectural decision rather than being treated as an absence.

## Decision

**Noxel ships no UI toolkit, no menu system and no editor.** What it ships
instead:

1. **`noxel-debug`** — a statistics system with rolling percentiles and section
   budgets, an overlay that draws text panels and a frame-time graph into the
   framebuffer, and a headless frame dumper with an image diff.
2. **`noxel-render::overlay`** — the drawing primitives those are built from:
   lines, boxes, rays, screen rectangles, a built-in 3x5 font and panels. It draws
   into the **linear** framebuffer using the exact linear value of the requested
   sRGB colour, so an overlay in `#FF0000` resolves back to exactly `#FF0000`.
3. **Documentation** — `docs/`, with an architecture overview, a getting-started
   guide, module guides, an API reference and this ADR set.

The debug overlay is explicitly *not* a UI framework. It draws; it does not
layout, focus, route input or theme. It exists so a developer can see what the
visibility, physics and NPC systems are doing — a culling bug is close to
unguessable from a screenshot and obvious the moment you can see the occluder
boxes and the camera-to-player ray.

## Consequences

- A game built on Noxel brings its own UI, or draws one with
  `noxel_render::overlay`. `docs/guides/ui.md` sketches the second option.
- The engine has no notion of a "screen" or a "state machine" above the plugin
  level. A plugin is the unit of composition, and a menu is a plugin.
- Text rendering is a 3x5 uppercase bitmap font. That is enough for a debug
  readout and deliberately not enough for dialogue; a game that needs text
  brings a font atlas, which `noxel-asset::atlas` packs.

## Alternatives rejected

- **An immediate-mode UI library**: a large subsystem with a large surface, and
  one that would need a windowing layer (which ADR 0002 rules out for the default
  build).
- **A retained-mode scene-graph UI**: worse for a debug overlay, and it would
  tempt game code into using it for gameplay UI, which the requirement excludes.

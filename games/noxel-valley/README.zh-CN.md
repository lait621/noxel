# 星野农场 · Noxel Valley

基于 Noxel 引擎开发的可玩俯视角种田游戏，同时也是引擎 UI 层的参考项目。

```bash
cargo run -p noxel-valley --features window -- --window      # 直接开玩
cargo run -p noxel-valley -- --frames 300 --dump frames       # 逐帧导出 PNG
```

如果只想**玩**，不需要编译任何东西：仓库根目录已经有构建好的发行包，见下面的
「怎么玩」。

---

## 这是什么

一张 44×34 瓦片的地图，上面有一栋农舍、一家种子店、一个出货箱。你翻土、播种、
浇水、等待、收割，然后卖钱。四季每 28 天轮换一次，换季时地里的作物会枯萎。

```text
  06:00   起床，体力恢复。今天的天气昨天晚上就决定了。
    ...   翻土 → 播种 → 浇水 → 收割 → 放进出货箱 → 睡觉
  02:00   强制上床
          |
          v
      1. 出货箱里的东西卖掉，金币到账
      2. 下雨会把整片田地浇好
      3. 浇过水的作物长一天；过季的作物枯死
      4. 清空今天的浇水状态
      5. 掷出明天的天气
      6. 日历前进一天
```

顺序本身就是设计。先下雨再生长，"雨天"对玩家才是白送的休息日；先生长再清空，
昨天的浇水才算数；最后清空，今天才会从干燥开始。

### 有什么系统

| 系统 | 内容 |
|---|---|
| **种植** | 翻土、播种、浇水、收割。六种作物，每种五个生长阶段；分属两个季节；两种可以收割后再生。作物在季节结束时枯死。 |
| **时间** | 一天 20 小时（06:00 到次日 02:00），现实每秒推进 2 游戏分钟，所以一天约十分钟。四季各 28 天，带年份计数和每日结算。 |
| **天气** | 晴、多云、雨、雷雨、雪，按季节加权，附三天预报。雨和雷雨会替你浇整片田；雪不会，因为冬天什么都长不出来。 |
| **交易** | 起始 500 金，24 格背包，种子店只卖当季种子，出货箱第二天早上结账。种子卖价是买价的一半，所以倒买倒卖一定亏。 |
| **玩家** | 走路与奔跑，工具和走路都消耗体力，六格快捷栏，工具作用在面朝的那一格。 |
| **UI** | 时钟与天气面板、钱袋、体力条、快捷栏、24 格背包、种子店、出货箱、早晨结算、操作说明——全部由 `noxel-ui` 绘制。 |

## 怎么玩

### 用现成的发行包

`dist/noxel-valley/` 是自包含的：可执行文件、资源和一个 `README.txt`。它不需要
Rust 工具链、不需要源码树、不需要联网。

```bash
cd dist/noxel-valley && ./noxel-valley --window
```

macOS 上 `dist/Noxel Valley.app` 是可以直接双击的应用程序包——**开箱即玩**。

### 从源码运行

```bash
cargo run -p noxel-valley --features window -- --window
```

`window` 特性默认关闭，这样引擎自身的 `cargo build` 依然不下载任何东西
（见 `docs/adr/0002-no-dependencies.md`）。打开它才会引入 `winit` 和
`softbuffer`，而它们被 `noxel-window` 关在同一个特性后面。

### 操作

| 按键 | 作用 |
|---|---|
| `WASD` / 方向键 | 走路 |
| `Shift` | 奔跑 |
| `空格` / 鼠标左键 | 使用手上的工具 |
| `1`–`6` / 滚轮 | 切换快捷栏 |
| `Tab` | 背包 |
| `E` | 种子店 / 出货箱 / 睡觉——看你站在哪旁边 |
| `?` | 操作说明 |
| `Esc` | 关闭界面，或退出 |

### 命令行

```text
--window        在窗口里玩，需要 `--features window`。
--frames N      跑 N 帧后停止。
--seed N        世界与天气随机种子（十进制或 0x 前缀）。
--fast          时钟加速 24 倍，一分钟过一个季节，方便测试。
--stats         打印一帧的统计后退出。
--dump DIR      把每一帧写成 PNG 到 DIR。
--assets DIR    资源根目录，默认自动查找。
--screen NAME   启动时直接打开某个界面：inventory / shop / bin / summary。
```

`--screen` 是为了截图方便：想拍商店的图，不必先走到商店门口。本文档里的界面图
就是这么来的。

## 目录结构

```text
games/noxel-valley/
  Cargo.toml
  README.md              英文说明
  README.zh-CN.md        本文件
  src/
    lib.rs               游戏规则，作为库导出
    main.rs              参数解析、资源加载、主循环
    config.rs            全部数值与数据表
    world.rs             瓦片网格、农场地形、由它生成的网格
    player.rs            移动、朝向、挥动工具、屏幕坐标转瓦片
    sim.rs               时钟、天气、背包、经济
    assets.rs            查找与加载图集和字体
    skin.rs              由图集构建 UI 主题
    ui.rs                玩家能看到的每一个界面
  assets/                生成产物，见下
    farm/                terrain / crops / props / characters / ui 的 PNG + JSON
    fonts/               UI 字体图集与度量
```

资源是**生成的**而不是手绘的，并且刻意与代码分离：`src/` 里没有任何像素数据，
`assets/` 里没有任何代码。

### 重新生成资源

```bash
# 精灵：五个图集，141 个区域
cargo run -p noxel-gen -- farm --out games/noxel-valley/assets

# 字体：手工绘制的 5x7 拉丁字面 + GB2312 常用汉字
python3 tools/fontgen/fontgen.py --out games/noxel-valley/assets/fonts

# 全部精灵的联络表，用来看效果
cargo run -p noxel-gen -- farm --out /tmp/farmart
open /tmp/farmart/farm/preview.png
```

两个生成器都是确定性的：跑两遍不会改变任何字节，所以 `assets/` 出现 diff 就
意味着真的变了。

游戏**不依赖**这些资源也能跑。没有资源树时它会退回到纯色块和引擎默认主题——
这正是 `cargo test` 能在毫秒级、磁盘上没有任何文件的情况下构建出一个可用游戏的
原因。

## 实现要点

### 一帧的流程

游戏是一个 `noxel_app::Plugin`，这样就白拿了整个循环：

```text
  App::step(dt)
    fixed_update    ValleyPlugin::update
                      玩家移动、使用工具、时钟、跨天
    frame_update    相机跟随 update() 设置好的 app.context.focus
    render          每个图集一个网格
    draw_overlays   ValleyPlugin::draw   <- 整个 UI
    resolve         线性 HDR -> sRGB，每帧一次
```

在 `draw` 而不是 `resolve` 之后画 UI 是关键：界面和世界在同一个线性空间里合成，
同一条色调曲线作用于两者，主题里写的 `#FF0000` 解析回屏幕上就是 `#FF0000`。

### 清晰度来自三个必须一致的决定

1. **相机**沿正交轴垂直向下，正交高度 `270 / 16 = 16.875`，于是**一个世界单位
   正好是 16 个屏幕像素**，两个方向都是。瓦片永远不会被重采样。用倾斜相机会让
   地面产生透视压缩，并把每个直立精灵按 `cos(pitch)` 缩放——那正是这套美术想
   避免的模糊。
2. **渲染器**用带半纹素内缩的最近邻采样（`Texture::sample_pixel_art`），相邻
   图集单元之间不会渗色。
3. **窗口**只按整数倍放大，余数留黑边；同一份推导反过来把光标映射回画布——所以
   在任何窗口尺寸下，点击都落在玩家瞄准的那个像素上。

### 不用排序的深度

世界里的一切都是地面平面上的扁平四边形。两块精灵重叠时需要从后往前绘制，而在
垂直向下的相机下，世界的 `z` **就是**屏幕深度——所以每个四边形按 `z` 给一个很小
的 `y` 偏移，深度缓冲自己就排好了。这就是画家算法，只是换成了光栅器本来就实现的
形式。

### 三个网格

地面、作物和道具是三个独立网格，因为一个材质只带一张纹理，而它们来自三个图集。
分开还有一个好处：地面材质可以带上季节色调，而作物保持真实颜色——南瓜不该因为
草变黄而变得更橙。

地图的修订号一变就重建农场网格，玩家翻土时大约每秒几次。44×34 瓦片约六千个顶点，
做增量更新只是为一个没人能测出来的开销写更多代码。

## 测试

```bash
cargo test -p noxel-valley            # 85 个测试
```

规则被当作规则来测，不需要渲染器：

- 每种作物在一个季节内都能回本，且没有哪种种能赚回成本的八倍以上
- 没浇水的作物不长；浇了水的正好长一天
- 下雨会把每一块翻过的地浇一次，且只浇一次
- 作物在季节结束时枯死
- 天气对同一种子是确定的，预报是滑动而不是重掷
- 背包满了会如实报告装不下的数量，而不是悄悄扔掉
- 玩家朝任意方向走都不会卡进实体格
- 出生点是可站立的

渲染契约则用**真实资源**验证：

- 发行图集能加载，农场进入场景，并且**真的画出了像素**——剔除系统接受一个实例
  不等于光栅器会画它；绕序反了的网格能通过所有剔除，然后在逐个三角形那里被全部
  拒绝。

## 已知的不足

按玩家会注意到的顺序，如实列出：

- **作物第 1、2 阶段是小色块。** 六种作物的第 4 阶段都很清楚，前两阶段是通用的
  嫩芽。
- **只有一个村民，没有对话。** 农场看起来有人住，但还不像一个小镇。
- **没有存档。** 退出就丢了这一季。
- **冬天按设计休耕**——什么都种不了——而且目前也没有别的事可做。
- **走路动画是 1–2 像素的腿部摆动。** 动起来像在走路，但四帧并排看很相似。
- **`log`、`crate`、`sprinkler` 是最朴素的三个道具**，六种种子袋也只是色带不同。
